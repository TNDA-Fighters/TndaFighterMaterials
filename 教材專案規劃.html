TNDA：UE 5.8 單機 3D 格鬥遊戲｜教材專案規劃

week-02｜雙角色入場與基礎格鬥攝影機

專案展示內容

Play 後直接進入 stage1。PlayerController Possess 1P，CPU 由場上的 Spawner 生成並保持原位；1P 可使用 W／A／S／D 移動。

  • 場上固定存在 1P 與 CPU，兩者依指定出生位置站定位；PlayerController 只控制 1P。
  • CPU 生成時先朝向 1P 的出生位置，但本週不會持續自動轉向，也不會自主移動。
  • 1P 的移動方向以實際格鬥攝影機為基準；本週尚未把 A／D 正規化為 4／6。
  • 1P 靜止、移動及受阻時會播放對應的 locomotion 動畫，放開輸入後回到 Idle。
  • PlayerController 建立共用 CameraActor；取得 1P 與 CPU 後，攝影機切換到雙人構圖。
  • 攝影機每幀追蹤雙方中點，讓兩名角色保持在畫面內且站位線維持水平，並將可見遊戲區固定為 16:9。
  • 雙方距離改變時，攝影機會平順拉近或拉遠，且不超過設定的最小與最大鏡頭距離。
  • 1P 與 CPU 換邊時只交換畫面左右位置，攝影機不會瞬間翻轉 180 度。
  • 兩名角色重疊或距離近到無法可靠計算戰鬥軸時，攝影機維持目前角度，不會突然跳向另一側。
  • 現版另有限制 1P 與 CPU 的最大距離，用途是維持雙人構圖；這不是場地外圍碰撞，正式戰鬥區域限制留到 week-04。

核心導入技術

Gameplay Framework／SpawnActor／Pawn Possession、Enhanced Input、Animation Blueprint／Blend Space、CameraActor／SpringArm、戰鬥中點／垂直向量／距離插值／換邊旋轉策略

week-03｜相對方向與自動面向

專案展示內容

建立雙方共用的戰鬥軸與對手參照。實體移動輸入先轉成相對於對手的方向語意，角色在一般移動期間持續轉向對方。

  • 1P 位於 CPU 左側時，A／D 會分別判定為後退 4 與前進 6。
  • 1P 與 CPU 換邊後，相同實體按鍵的 4／6 意義同步反轉。
  • 方向事件在產生時就保存 4／6 語意；後續換邊不回頭修改已記錄的方向。
  • 1P 與 CPU 在待機及移動期間會持續面向對方，換邊後能平順轉身。
  • 雙方重疊或距離太近時沿用上一個有效面向，避免左右方向與角色旋轉反覆跳動。
  • 相對方向與自動面向共用同一份對手位置及戰鬥軸判定，避免兩套規則互相矛盾。

核心導入技術

Opponent Reference、戰鬥軸、4／6 相對方向正規化、Vector／Dot Product、Look At Rotation／Rotation Interpolation

week-04｜戰鬥區域碰撞限制

專案展示內容

以場地碰撞圍出可移動的戰鬥區域，讓角色留在區域內。本週只處理不可穿越的邊界，不實作 Ring Out。

  • 1P 與 CPU 都無法穿過戰鬥區域外圍的碰撞邊界。
  • 角色持續朝邊界移動時不會穿牆、瞬移到場外或持續抖動。
  • 角色碰到邊界後仍可往場內移動，也可沿邊界移動。
  • 場地邊界與 week-02 的雙方最大距離限制各自負責不同規則，不互相取代。
  • 攝影機在角色接近場地邊界時仍維持雙人構圖。
  • 角色碰到場地邊界不會觸發勝負，本週沒有 Ring Out 判定。

核心導入技術

Blocking Volume、Collision Preset／Channel Response、CharacterMovement Collision、場地邊界配置

week-05｜基本攻擊與 Animation Montage

專案展示內容

使用既有 MM_Attack_01 AnimSequence 建立可播放及編輯的 AM_Attack_01 Animation Montage。U 鍵是本週的測試鍵，按下後送出攻擊語意 X。

  • 可在 Montage Editor 編輯 AM_Attack_01 的動畫片段、Slot、Blend In 與 Blend Out。
  • 按下 U 鍵後，1P 完整播放一次 AM_Attack_01。
  • 攻擊期間限制角色移動與自動面向，避免攻擊動作被一般移動規則覆蓋。
  • 攻擊正常結束或被中斷時，都會離開攻擊狀態並恢復合法操作。
  • 攻擊中重複按鍵不會疊加 Montage，也不會讓角色卡在攻擊狀態。
  • 本週只有攻擊動畫與動作生命週期，尚未加入 Hitbox、Hurtbox、扣血或連段。

核心導入技術

Animation Montage、Anim Slot、Montage Playback、Montage Callback、Action Lock／Input Gating

week-06｜Command DataTable 與資料驅動放招

專案展示內容

建立 Command CSV、FTableRowBase 資料結構與 Command DataTable。攻擊入口依語意指令 X 查表取得 AM_Attack_01，不再由程式硬編碼 Montage。

  • U 鍵透過 Input Mapping Context 送出 X，Command DataTable 再將 X 對應到 AM_Attack_01。
  • 修改 CSV 的 Montage 或招式設定並 Reimport 後，下一次放招會使用更新後的資料。
  • 程式碼不再直接指定 AM_Attack_01。
  • 在 Input Mapping Context 將 I 鍵加入同一個攻擊 Input Action 後，不修改 C++ 也能用 I 鍵播放 A 招。
  • 無效 Row、空 Montage 或與角色 Skeleton／Slot 不相容的資料會拒絕執行並留下 Log。
  • Command DataTable 不保存 U、I 等實體鍵名；實體鍵位仍由 Enhanced Input 負責。

核心導入技術

DataTable／CSV Reimport、FTableRowBase、Command Row Lookup、Input Mapping Context、資料驗證

week-07｜Hitbox、Hurtbox 與資料驅動傷害

專案展示內容

建立獨立的 Damage CSV／DataTable、角色生命值，以及攻擊用 Hitbox 與受擊用 Hurtbox。Command Row 只保存 Damage Row 的參照；實際扣血值由 Damage DataTable 提供。

  • 在 AM_Attack_01 加入 Damage Notify State，並以時間範圍標示可造成傷害的 Active 階段。
  • Damage Notify State 開始時啟用 Hitbox，結束時停用；範圍外不會造成傷害。
  • 1P 的 Hitbox 接觸 CPU 的 Hurtbox 時判定命中，並依 Damage Row 扣除 CPU 生命值。
  • 本週先以單一 Hurtbox 驗證一次攻擊、一次碰撞與一次扣血流程；多 Hurtbox 的重複命中防護留到 week-08。
  • Damage Notify State 不保存第二份傷害值，只傳遞目前攻擊的命中時機。
  • 尚未建立正式 HUD 時，可由 Log 或開發用除錯資訊確認命中 Row、傷害值與剩餘生命值。

核心導入技術

Damage DataTable、Hitbox／Hurtbox、Anim Notify State、Overlap Collision、Health Component

week-08｜Frame Data 與 Command Link 執行模型

專案展示內容

正式建立 Startup、Active、Recovery 的 Frame Data 執行模型，並用 Montage 時間軸上的 Notify 控制輸入預約、接招時機與 Recovery 起點。Frame 是設計及驗收單位；執行階段依 Montage 時間與事件運作，不以 Tick 累加整數幀。

  • CommandLinkPreorderNotify 觸發後開始接收一筆待處理指令，並記錄到 CommandBuffer。
  • CommandLinkEnableNotify 觸發時檢查 CommandBuffer；若指令有效且是合法後續招式，就消耗該指令並開始下一招。
  • CommandLinkDisableNotify 觸發後關閉接招機會，之後輸入不會回溯生效，角色進入 Recovery。
  • Preorder 前的輸入不會被錯誤預約；Buffer 過期、攻擊結束、Montage 中斷、受擊、KO 或 Reset 時都會清除待處理指令。
  • 同一次揮擊即使碰到同一角色的多個 Hurtbox，也只會扣一次血。
  • 修改 Damage CSV 並 Reimport 後，下一次命中會使用新數值，不需重建 Hitbox 或 Notify。
  • 本週完成可供連段使用的 Link 與 Buffer 基礎；正式連段內容在 week-11 加入。

核心導入技術

Frame Data、CommandBuffer、Command Link Notify、單次揮擊命中集合、中斷與結束清理

week-09｜CPU AI 接近與選招

專案展示內容

建立 CPU 的基本決策流程。CPU 根據與 1P 的距離決定接近或攻擊，並呼叫玩家共用的選招與攻擊入口，不模擬鍵盤輸入。

  • CPU 距離過遠時會朝 1P 接近，進入攻擊距離後停止追趕。
  • CPU 生成後由 AIController Possess，並由 StateTree 管理接近、攻擊與等待下一次決策的流程。
  • 進入攻擊距離後，CPU 會從 Command DataTable 選出目前可用的招式。
  • CPU 執行招式時沿用 week-05～week-08 的 Montage、Hitbox、傷害與 Command Link 流程。
  • CPU 在攻擊或尚未恢復行動時不會重複下攻擊指令。
  • 玩家與 CPU 在相同條件下會通過同一套資料驗證與招式合法性檢查。
  • 本週 CPU 尚未防禦；防禦與硬直狀態留到 week-10。

核心導入技術

AIController、StateTree、Evaluator／Task／Transition、距離決策、玩家與 AI 共用攻擊介面

week-10｜防禦、硬直與集中式戰鬥狀態

專案展示內容

建立 Neutral、Attacking、Defending、Hitstun、Blockstun 與 KnockedOut 等集中式戰鬥狀態。命中流程依 Defense Intent 決定進入一般受擊或防禦結果。

  • 防禦成功時不進入一般受擊流程，改為 Blockstun。
  • 一般命中會進入 Hitstun；Hitstun／Blockstun 到期後，角色回到合法狀態。
  • Damage DataTable 提供傷害與硬直時間，Hitbox、Hurtbox 及 Notify 不保存重複數值。
  • 角色在 Hitstun、Blockstun 或 KnockedOut 期間不能移動、攻擊或重複接受不合法指令。
  • tnda.Debug.CPUDefense on|off|auto 可將 CPU 防禦固定為開啟、關閉或交還 AI 控制。
  • tnda.Debug.PrintFighters 可輸出雙方目前戰鬥狀態、生命值、目前招式與硬直剩餘時間。
  • Console 指令呼叫正式戰鬥介面，不直接寫入角色內部狀態。

核心導入技術

Combat State Machine、Defense Intent、Hit Resolution、Gameplay Timer、自訂 Console 指令

week-11｜基本連段

專案展示內容

以 Command DataTable 定義三段基本連段。AM_Attack_01～03 是由對應 MM_Attack_01～03 AnimSequence 建立的可播放 Montage；本週的第三段刻意再次使用 AM_Attack_01。

X       → AM_Attack_01
XX      → AM_Attack_02
XXX     → AM_Attack_01
  • 單按 X 只播放第一段，符合 Link Window 時再次按 X 才會進入第二段與第三段。
  • 太早、過期或在 CommandLinkDisableNotify 之後輸入，不會錯誤接段。
  • 即使第一段與第三段使用同一個 Montage，兩者仍保有不同的連段步驟身分，不會形成錯誤循環。
  • 攻擊正常結束或中斷時，連段步驟與待處理指令都會清除。
  • CPU AI 可依相同 Command Row 與 Follow-up 規則完成三段連段。
  • 本週只有 X 的線性連段，尚未加入 6X 分支。

核心導入技術

Combo Step／Chain State、Allowed Follow-up、Pending Command Consumption、資料驅動連段、玩家與 AI 共用連段入口

week-12｜相對方向分支連段

專案展示內容

在基本連段加入 6X 分支，並沿用 week-03 的相對方向與 week-08 的 CommandBuffer。

X       → AM_Attack_01
XX      → AM_Attack_02
XXX     → AM_Attack_01
XX6X    → AM_Attack_03
  • 第二段後按 X 會進入 AM_Attack_01，按住相對前方 6 再按 X 則進入 AM_Attack_03。
  • 6X 與 X 同時符合時，較具體的 6X 分支優先。
  • 方向在輸入寫入 CommandBuffer 時就保存；之後換邊不會把已記錄的 6X 改成 4X。
  • 換邊後的新輸入會依新朝向重新判定 4／6。
  • 不合法、過期或不在 Link Window 內的方向攻擊不會接段。
  • CPU AI 可直接提供相對方向語意，並透過同一套分支規則選擇普通第三段或 6X 分支。

核心導入技術

Command Pattern Matching、方向輸入快照、Context Snapshot、分支具體度／優先規則、資料驅動分支

week-13｜回合基本流程與自動再戰

專案展示內容

建立 Preparing、Ready、Fight 與 RoundOver 等回合狀態。任一方生命值歸零時產生唯一的 Round Result，寫入 Log，等待 2 秒後完整重設並自動開始下一場。本週尚未加入正式 Round Timer 與結算 UI。

READY → FIGHT → KO → Round Result Log → 等待 2 秒 → Reset → 下一場 READY
  • FIGHT 前玩家與 CPU 都不能行動，倒數結束後才開放戰鬥。
  • KO 後停止輸入、AI、攻擊與傷害，每場只產生一次 Round Result。
  • Log 正確顯示 Round、勝負、結束原因與雙方剩餘生命值。
  • 結算後等待 2 秒，自動重設位置、生命值、Montage、Timer、CommandBuffer、輸入與戰鬥狀態。
  • 連續進行多場時，不會殘留上一場的角色狀態、Hitbox、Command Link 或回合事件。
  • 提供開發用情境指令，可快速觸發 1P KO、CPU KO 與回合重設；最終結果仍由正式回合規則產生。

核心導入技術

Round State Machine、READY／FIGHT Gating、KO 判定、Round Result、Round Reset

week-14｜倒數計時與特殊結算

專案展示內容

加入 Round Timer、Time Over 與 Draw。傷害與時間到期先進入 Pending Resolution，再由單一入口依固定優先順序結算，避免 KO 與 Time Over 在同一幀產生兩次結果。

結算優先順序如下：

  1. 雙方生命值同時歸零：Double KO／Draw。
  2. 只有一方生命值歸零：另一方以 KO 獲勝。
  3. 雙方都未歸零且時間到：生命值較高者獲勝，同血量為 Draw。
  • 時間歸零時依雙方生命值正確判定勝負或 Draw。
  • KO 與 Time Over 同時發生時，只會依上述優先順序結算一次。
  • Log 顯示 Reason、雙方剩餘生命值與剩餘時間。
  • 結算後仍沿用 week-13 的 2 秒等待、完整 Reset 與自動再戰。
  • 提供以下開發情境指令：
tnda.Debug.RoundScenario double_ko
tnda.Debug.RoundScenario timeover_draw
tnda.Debug.RoundScenario ko_at_timeout
tnda.Debug.RoundScenario player_timeover_win
tnda.Debug.RoundScenario cpu_timeover_win
  • 情境指令只建立測試條件，不直接偽造 Round Result。

核心導入技術

Round Timer、Time Over、Pending Resolution、Double KO／Draw、結算優先規則

week-15｜戰鬥 HUD 與結算 UI

專案展示內容

建立事件驅動的 Battle HUD，顯示 1P／CPU 生命值、倒數時間、READY／FIGHT 與連段資訊。回合結束後顯示勝負或 Draw，並停用 week-13～week-14 的自動再戰。

  • HUD 會隨生命值、時間與回合事件更新，不使用 Tick 輪詢戰鬥資料。
  • 結算畫面讀取 Round 系統產生的同一份 Round Result，正確顯示 1P 勝、CPU 勝或 Draw。
  • 結算 UI 顯示期間不會自動開始下一場。
  • <再來一局> 會執行完整 Round Reset，重新進入 READY／FIGHT 流程。
  • <回主選單> 本週只輸出尚未實作的 Log，不切換場景。
  • 連續操作 <再來一局> 不會重複建立 HUD 或綁定相同事件。

核心導入技術

UMG、事件驅動 UI、Battle HUD、Result UI、Widget 按鈕事件

week-16｜戰鬥特效與音效

專案展示內容

示範 Niagara System 與 Emitter 編輯，製作 Hit、Block 與 Combo 的視覺回饋及一次性音效。C++ 命中結算只送出戰鬥表現事件，由 Blueprint 依事件資料選擇 Niagara 與音效。

  • Hit、Block 與 Combo 會播放不同特效及音效。
  • 特效可接收接觸位置、方向或強度等 User Parameter。
  • 音效由戰鬥事件觸發一次，不會因 Niagara 粒子數量重複播放。
  • tnda.Debug.PlayFeedback hit|block|combo 可在不進行完整戰鬥時預覽表現效果。
  • 關閉或移除特效後，傷害、防禦、戰鬥狀態、連段及回合結果都不受影響。
  • KO 或 Round Reset 會清除尚未完成的戰鬥特效與音效元件，不殘留到下一場。

核心導入技術

Niagara System／Emitter、User Parameter、One-shot Audio、C++／Blueprint 事件串接、戰鬥規則與表現分離

week-17｜主選單、非同步載入與完整遊戲流程

專案展示內容

建立主選單與對戰準備畫面，使用 Soft Reference 非同步載入戰鬥場地、角色、動畫、Niagara 與音效，並正式接通 week-15 的 <回主選單>。

主選單
→ 對戰準備／非同步載入
→ READY／FIGHT
→ 戰鬥
→ 結算
→ 再來一局或回主選單
  • 主選單不直接硬參照戰鬥資產。
  • 載入期間顯示目前階段與 Spinner，不顯示無法可靠計算的假百分比。
  • 必要資產載入完成後才建立戰鬥；載入失敗時不留下半套場景，並可安全回主選單。
  • 快速連按開始不會建立重複的載入請求或戰鬥流程，過期回呼不會污染新請求。
  • <再來一局> 沿用已載入資產，略過準備畫面並完整重設戰鬥。
  • <回主選單> 會停止戰鬥、銷毀本局物件、卸載場地、釋放非同步 Handle 並回到選單。
