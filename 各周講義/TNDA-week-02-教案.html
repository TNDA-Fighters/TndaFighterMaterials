課前預習

課前實作練習 1｜比較 PIE 前後的 World Outliner

細步驟解答

  1. 停止 PIE，開啟 stage1。在 World Outliner 找到 PlayerStart 與 CPU_Spawner，這兩個物件原本就在關卡中。
  2. 開始 PIE，按 F8 切換到模擬模式。在 PIE 的 World Outliner 找到 1P、CPU 與 FightingCameraActor，這三個物件都是開始遊戲後才產生。
  3. 分組答案如下：關卡原有物件是 PlayerStart、CPU_Spawner；執行時產生的物件是 1P、CPU、FightingCameraActor。
  4. PlayerController Possess 1P，所以玩家控制的是 1P；目前的 View Target 是 FightingCameraActor，負責提供雙人構圖畫面。
  5. 停止 PIE，本題沒有修改場景或參數，不需要還原設定。

課前實作練習 2｜調整格鬥攝影機參數

細步驟解答

  1. 對照學生講義的架構流程，找出角色距離限制與鏡頭距離映射兩條流程。
  2. 啟動 PIE，按 F8 Eject，在 PIE World Outliner 選取 FightingCameraActor。
  3. 記錄 Fighting Camera > Distance 的原始值：MinCameraDistance=440、MaxCameraDistance=690、MinFighterDistance=110、MaxFighterDistance=570。
  4. 將 MaxFighterDistance 暫時改為 900，並把 MaxCameraDistance 改為 850。重新控制 1P 後拉開雙方距離；1P 可離 CPU 更遠，攝影機也會使用較長的 SpringArm 保留雙人構圖。
  5. 將 MinCameraDistance 暫時改為 320，讓雙方靠近。近距離構圖會更貼近角色；這項設定不會改變角色可以分開的最遠距離。
  6. 用修改前後的近、遠距離畫面比較結果。MaxFighterDistance 限制角色最遠能站多遠，MinCameraDistance 與 MaxCameraDistance 則限制攝影機能拉多近或多遠。
  7. 停止 PIE，再次執行並確認所有執行時數值已恢復。

課堂示範

課堂示範 1｜說明 TndaFighter 基礎架構

示範重點

  • 從 stage1 開始，先區分關卡中原本就有的 PlayerStart、CPU_Spawner，以及進入 PIE 後才產生的 1P、CPU 與 FightingCameraActor。
  • AFightingGameMode 負責指定玩家使用的類別，並從 PlayerStart 決定 1P 的出生位置。
  • AFightingCpuSpawner 從 Spawn Capsule 生成 CPU，再讓 CPU 朝向 1P 的出生位置。
  • AFightingPlayerController Possess 1P，同時建立 AFightingCameraActor。藉此說明 Possession 決定玩家控制誰，View Target 決定畫面從哪裡取景。
  • AFightingCameraActor 取得 1P 與 CPU 後，依雙方位置更新共同焦點、取景方向與鏡頭距離，最後成為 PlayerController 的 View Target。
  • 收尾時把四個類別串回完整流程：決定 1P 出生點、生成 CPU、建立攝影機、切換 View Target、持續更新雙人構圖。

課堂示範 2｜說明 ABP 概念

示範重點

  • 以 ABP_Manny_Combat 為例，先說明 AnimBP 負責根據角色狀態選擇動畫，不負責移動角色。
  • 區分 EventGraph 與 AnimGraph：EventGraph 取得並整理角色資料，AnimGraph 使用這些資料產生最後的 Animation Pose。
  • EventGraph 每次更新會從 CharacterMovementComponent 讀取 Velocity、Current Acceleration 與 Falling 狀態，再計算 Ground Speed、Direction、Should Move 和 Is Falling。
  • Locomotion State Machine 依 Should Move 在 Idle 與 Walk / Run 之間切換；Walk / Run 再把 Direction 和 Ground Speed 交給 BlendSpace 混合動畫。
  • Main States 使用 Is Falling 處理地面移動、跳躍與落地之間的狀態切換。
  • 補充目前專案如何處理「有移動輸入，但角色無法繼續位移」的情況：
    • 玩家持續按住方向鍵時，Current Acceleration 仍然不是零，代表玩家還想移動。
    • 角色撞到 CPU 或抵達最大距離邊界後，CharacterMovementComponent 的真實 Velocity 可能降到接近零。如果 AnimBP 直接使用這個速度，Ground Speed 也會接近零，Should Move 變成 false，角色就會從 Walk / Run 切回 Idle。
    • ABP_Manny_Combat 會同時檢查移動輸入與真實速度。仍有輸入，而且真實速度不高於 Blocked Movement Animation Speed 時，AnimBP 會依輸入方向產生 300 cm/s 的替代 Velocity，讓 locomotion 繼續播放。
    • 替代 Velocity 只寫入 AnimBP 的 Velocity 變數，供 Ground Speed、Direction 與 BlendSpace 選擇動畫。它不會改寫 CharacterMovementComponent.Velocity，也不會讓角色穿過 CPU 或突破最大距離限制。
    • 玩家放開方向鍵後，Current Acceleration 回到零，AnimBP 停止使用替代 Velocity，Should Move 變成 false，角色正常回到 Idle。

課堂實作

課堂實作 1｜對調 1P 與 CPU 的初始位置

題目

交換 1P 與 CPU 的初始水平位置，各自保留原本的高度與縮放。再調整必要的初始朝向，讓兩名角色進入 PIE 後仍面對彼此，並保留原有雙人攝影機功能；不要新增或修改程式碼。

參考答案

  1. 停止 PIE。在 World Outliner 搜尋並選取 PlayerStart 與 CPU_Spawner，記錄兩者原始 Transform。
  2. 交換兩者 Location 的 X、Y，保留各自原本的 Z 與 Scale，CPU_Spawner 的 Rotation 也維持不變。教材內的 Spawn Capsule 只相對 CPU_Spawner 向上 90 cm，因此 CPU 的初始水平位置會跟著 Spawner 移動。
  3. 選取 PlayerStart，按 E 切換到旋轉工具。在 Viewport 上方工具列找到 Coordinate Space 圖示；World 模式會顯示地球圖示，按一下後會切換成 Local 的立方體座標軸圖示。也可以按 Ctrl + 反引號鍵切換。沿本地 Z 軸調整 Yaw，讓 PlayerStart 的箭頭指向移動後的 Spawn Capsule。CPU_Spawner 不必旋轉，CPU 生成後會自動朝向 PlayerStart。
  4. 進入 PIE，不輸入移動。確認 1P 與 CPU 已交換初始位置，而且仍互相面對。若 1P 朝向不正確，停止 PIE 後繼續調整 PlayerStart 的本地 Yaw。
  5. 不必移動攝影機。FightingCameraActor 會依兩名角色的新位置重新構圖；PlayerController 控制的 Pawn 仍是 1P，View Target 仍是 FightingCameraActor。

課堂實作 2｜讓 CPU 生成 Log 顯示世界座標

題目

修改 Source/TndaFighter/Fighting/FightingCpuSpawner.cpp 內 CPU 生成成功時的 UE_LOG，讓 Output Log 同時顯示 CPU 的物件名稱與世界座標。只修改既有的 Log，不更動 CPU 的生成與朝向流程。完成後編譯 C++，進入 PIE 確認新的訊息格式。

參考答案

  1. 停止 PIE，開啟 Source/TndaFighter/Fighting/FightingCpuSpawner.cpp。
  2. 在 AFightingCpuSpawner::BeginPlay() 內找到 if (SpawnedCpu)，再找到成功生成後原本的 UE_LOG。
  3. 將原本的 Log 改成：
UE_LOG(
    LogTndaFighter,
    Log,
    TEXT("Spawned CPU: %s at %s"),
    *SpawnedCpu->GetName(),
    *SpawnedCpu->GetActorLocation().ToString());
  1. 儲存 .cpp，回到 Unreal Editor，按 Ctrl + Alt + F11 執行 Live Coding。確認編譯完成且沒有錯誤。
  2. 開啟 Output Log，再進入 stage1 的 PIE。
  3. 搜尋 LogTndaFighter。成功時會看到 CPU 物件名稱，以及包含 X、Y、Z 的世界座標。
