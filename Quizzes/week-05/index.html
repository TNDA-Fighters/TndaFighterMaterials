WEEK 05 · 實作測驗

雙人鍵盤對打

開啟測驗專案 ↗測驗題目與繳交內容實作對照與操作步驟

實作題：本地雙人鍵盤對打

題目

從 week-05 專案開始，把原本一人操作的格鬥遊戲改成兩人共用一把鍵盤。兩人要能同時移動、繞行、推擠與出拳，並沿用現有的角色、場地與相機。

操作方式

操作 1P 2P
移動 WASD ↑、↓、←、→
出拳 U Num7（數字鍵盤的 7）

實作提示

  • 先理解預設的輸入分配。 鍵盤輸入預設交給第 1 組 PlayerController（索引 0），後續本機玩家則使用搖桿。新增第 2 個 PlayerController 不會自動把同一把鍵盤的部分按鍵分給 2P。因此，本題沿用預設輸入配置時，兩組按鍵都要由 PlayerCharacter 接收，再把 2P 的指令轉發給 CpuCharacter。
  • 先把按鍵分開。 目前方向鍵也會控制 1P，要把它改成只控制 2P。可以新增 IA_P2Move、IA_P2Attack，在 IMC_Combat 設定方向鍵與 Num7。
  • 利用場上現有的 CPU 當 2P。 在 PlayerCharacter 綁定第二組 Input Action，透過現有的 GetOpponent() 取得 CpuCharacter，再轉發移動、停止移動與出拳指令，不必再生一個角色。
  • 兩人都依畫面方向移動。 參考 1P 現有的移動寫法，讓 2P 也使用同一個相機方向。不要用角色自己的朝向，否則換邊後按鍵方向可能跟著反轉。
  • 沿用原本的移動與出拳功能。 CPU 沒有玩家控制器，要確認它仍能移動。出拳可以呼叫現有 TryExecuteCommand("X")，讓既有程式處理動畫與出拳時暫停移動。

驗收

  1. WASD 與 ↑↓←→ 同時操作，確認移動、繞行、推擠功能有如預期。
  2. 同時按 U／Num7，兩方都同時出拳。
  3. 長按 → 時再按下 Num7，2P 會出完拳後繼續移動。

繳交內容

  1. Git commit 異動歷程：從 week-05 專案內容開始，隨實作進度分次 commit，保留可理解的 commit log。訊息要看得出這次改了什麼，例如「新增 2P 方向鍵與出拳按鍵」、「讓 CPU 接收第二組鍵盤操作」；不要全部做完後只留一筆「完成」或使用「update」等無法辨識內容的訊息。程式碼與 Input／Blueprint 資產都要納入版本控制。

雙人鍵盤對打：實作對照與操作步驟

目標與實際架構

同一把鍵盤、同一畫面操作兩名角色。保留一個 LocalPlayer 與 PlayerController，2P 沿用既有 CPU。

操作 1P 2P
移動 WASD ↑、↓、←、→
攻擊 U Num 7（NumPadSeven）

實際輸入綁定放在 AFightingPlayerCharacter::SetupPlayerInputComponent()；1P Character 轉送 2P 的軸值與視角，CPU 換算世界方向。這與原先「Controller 綁定、轉送世界向量」的計畫不同。

AFightingPlayerController 仍只掛載 IMC 並提供相機旋轉。GameMode 沿用出生、雙向配對與共用相機流程；不增加第二個 Controller 或分割畫面。

步驟一：設定 Input 資產

在 /Game/Fighting/Input/Actions/ 使用 IA_P2Move（Axis2D）、IA_P2Attack（Boolean），Action 均無額外 Trigger／Modifier。

/Game/Fighting/Input/IMC_Combat 的 Default Key Mappings 實際共 10 筆，無 Profile Override：

Action Key Mapping Modifier 輸出
IA_Move W Swizzle YXZ (0, 1)
IA_Move S Swizzle YXZ、Negate (0, -1)
IA_Move A Negate (-1, 0)
IA_Move D 無 (1, 0)
IA_Attack1 U 無 Boolean
IA_P2Move Up Swizzle YXZ (0, 1)
IA_P2Move Down Swizzle YXZ、Negate (0, -1)
IA_P2Move Left Negate (-1, 0)
IA_P2Move Right 無 (1, 0)
IA_P2Attack NumPadSeven 無 Boolean

Mapping 均無額外 Trigger。方向鍵只操作 2P；本版已移除原本的搖桿 mapping，與先前保留搖桿的計畫不同。

UE 5.8 Python 查詢須讀取 default_key_mappings.mappings；deprecated 的 mappings 可能為空，不能據此判斷資產沒有設定。

步驟二：1P Character 綁定與轉送

修改 FightingPlayerCharacter.h/.cpp。

資產欄位與事件

新增 EditDefaultsOnly 的 Player2MoveAction、Player2AttackAction，在 BP_FightingPlayerCharacter > Class Defaults > Input 指定兩個新 Action。

Action Event 回呼
Player2MoveAction Triggered OnPlayer2Move
Player2MoveAction Completed／Canceled OnPlayer2StopMove
Player2AttackAction Started OnPlayer2Attack

使用 1P 的同一個 Enhanced InputComponent；兩個 2P Action 分別檢查有效性，未指定時略過相應綁定。

共用視角

GetControllerRotator(FRotator& OutRotator) 抽出原本 1P 的視角查詢，由 1P DoMove() 與 2P 移動回呼共用：

  1. 沒有 Controller：回傳 false，不改寫輸出。
  2. 有 Controller：先取得 Control Rotation。
  3. Controller 為 FightingPlayerController 且實際 View Target 是格鬥相機：以相機旋轉覆蓋輸出。
  4. 呼叫端只取 Yaw。成功不代表相機一定有效，Controller Rotation 仍是合法備援。

轉送流程

OnPlayer2Move() 每次透過 Cast<AFightingCpuCharacter>(GetOpponent()) 取得配對對手，讀取 Axis2D，取得共同視角後呼叫：

player2->DoKeyboardMove(movement_vector.X, movement_vector.Y, controller_rotator);

對手或 1P Controller 無效時忽略移動。不在初始化時快取 CPU，也不搜尋替代對手。

OnPlayer2StopMove() 呼叫對手的 StopKeyboardMove()；OnPlayer2Attack() 在 Started 時呼叫 Attack()，不讀取 Boolean 數值，也不將它讀成 FVector2D。

步驟三：CPU 接收鍵盤操作

修改 FightingCpuCharacter.h/.cpp。實際介面：

void DoKeyboardMove(float right, float forward, const FRotator& controller_rotator);
void StopKeyboardMove();
void Attack();

移動與鎖定

從傳入旋轉取 Yaw，以 X 軸取得水平前方向、Y 軸取得水平右方向，分別呼叫 AddMovementInput()。CPU 不自行查詢 Controller 或相機。

攻擊含淡出期間，bIsAttacking 阻擋新移動。共同出招入口已清除待消耗輸入與速度；CPU 不保存額外鍵盤推擠意圖，ClearAttackMovementIntent() 沿用基底空實作。

兩軸合成與加速度限幅交給 CharacterMovement，不額外正規化斜向輸入。保留 bRunPhysicsWithNoController = true，讓無 Controller 的 CPU 仍可移動。

停止

StopKeyboardMove() 目前是空實作。CPU 不保存持續鍵盤輸入，Triggered 停止後不再追加；已排入的輸入仍由 CharacterMovement 消耗，速度依制動設定減速。

此入口不清除 Pending Input，也不強制清零速度。未來若保存持續意圖，須同步實作清理。

攻擊與速度

Attack() 僅呼叫 TryExecuteCommand(TEXT("X"))，沿用共同地面資格、單次 Montage、鎖定與淡出清理，不新增連發或排隊。

CPU 原生 MaxWalkSpeed 改為 400 cm/s；Blueprint 可覆寫。目前雙方 Class Defaults 均為 400。

步驟四：Blueprint 與對局設定

2026-09-30 MCP 已確認：

  • BP_FightingPlayerCharacter 的兩個 2P 欄位分別指定 IA_P2Move／IA_P2Attack。
  • BP_FightingPlayerController 掛載 IMC_Combat。
  • CPU 的 AutoPossessAI、TestMovementMode 均 Disabled；無 Controller 物理為 True。
  • 雙方 BasicAttackMontage 均為 /Game/Fighting/Anims/AM_Attack_01。

Test Movement 必須關閉，否則 CPU Tick 仍可能加入另一組移動輸入；鍵盤入口不會自動停用它。

沿用單一玩家登入、1P Possess、CpuStart 生成對手、雙向配對與共用相機。推擠仍由 1P 單一解算點處理。

限制與維護

  • 2P 仍是 CPU，沒有獨立 Controller 或獨立 4／6 快照。
  • 相機超距仍只修正 1P，2P 遠離可能帶走 1P。
  • 本版 IMC 只有鍵盤 mapping。
  • 沒有命中、傷害、血量、勝負、回合重置或模式切換。
  • 同步 Player／Cpu／Match 文件與 README；原始碼註解使用繁體中文、維持 CRLF。
