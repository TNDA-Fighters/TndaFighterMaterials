Week 08 實作題：命中推拉與鏡頭震動

從老師提供的 TndaFighter week-08 示範專案開始，用 C++ 擴充傷害資料與命中效果，運用 AI 協助實作，並透過 Unreal MCP 查核專案與資產。完成後，角色命中對手可以把對手推遠或拉近，指定招式擊中對手時會讓鏡頭短暫震動，即使沒有扣血也一樣。

作業安排為四天。沿用既有角色、動畫、場地與兩招接招功能，不需製作新 UI、美術或動畫。

實作要求

一、DamageTable.csv 新增 HitPushX 欄位

招式打中對手並造成扣血時，依 HitPushX 的數值，將對手平滑推遠或拉近。

設定 遊戲行為
負值，例如 -60 對手遠離攻擊者，要求移動 60 公分。
正值，例如 30 對手靠近攻擊者，要求移動 30 公分。
0 正常結算傷害，不產生推拉。

二、CommandTable.csv 的 CameraShot 新增 Shake 類型

招式設為 CameraShot=Shake 時，只要打中對手就觸發鏡頭震動，即使被防禦或沒有扣血也要震動。揮空不震動。

實作提示

新增系統時，先定義資料與介面，再規劃 Init → Tick → End，最後接入遊戲流程。 不要一開始就把所有邏輯塞進 Tick。

  • 定義資料與介面：先列出需要保存的狀態、初始值、對外方法與私有方法，決定誰擁有這些資料。
  • Init（啟動）：準備本次效果的資料，清除舊進度，開始效果。
  • Tick（更新）：依 DeltaSeconds 推進時間，計算本幀變化。
  • End（結束）：停止效果並清除狀態，讓下一次 Init 能重新開始。
  • 接入與測試：決定由誰、在什麼時機呼叫以上方法，再確認遊戲結果。

以下兩套功能都依這個順序實作。先在 header 宣告方法，再到 cpp 寫實作；Init 可以呼叫稍後才實作的 End。C++ 路徑皆相對於 Source/TndaFighter/，CSV 路徑相對於專案根目錄。資料欄位與 Reader 可先獨立建置、匯入確認；開始撰寫效果方法後，先完成該系統步驟 1～5，再完整建置與測試。

一、HitPushX：讓命中產生推拉

步驟 1：定義資料與介面

  1. 在 DataTable/TndaDamageData.h 的 FTndaDamageRow 與 FTndaDamage 都新增 float HitPushX = 0。Row 用於匯入，另一份是遊戲使用的副本。
  2. 在 DataTable/TndaDamageReader.cpp 將 CSV 表頭擴充為 ID,Title,Damage,HitPushX，補上正負十進位數字的完整解析、有限值檢查與 Row → 副本的複製；拒絕空白、NaN、Infinity、科學記號及尾隨文字。在 _DataTable/DamageTable.csv 每列補上新值，先設 0，並同步 DataTable/Tests/ 的 CSV 測試資料，保留各測例原本的驗證目的。
  3. 在 Fighting/FightingCharacter.h 的 private 區宣告推拉總位移、經過時間、啟用狀態，以及固定時長 0.15 秒。每個受擊角色各自保存狀態。
  4. 在同一 private 區宣告 InitHitPush(Distance, AttackerLocation)、TickHitPush(DeltaSeconds)、EndHitPush()。這些是角色內部方法；角色類別可呼叫另一個同類別實例的 private 方法，不必全部公開。

步驟 2：Init — 準備這次推拉

在 FightingCharacter.cpp 實作 InitHitPush()：先呼叫 EndHitPush 清除舊效果，再把「攻擊者位置減受擊者位置」的 Z 設為 0，正規化後乘上 HitPushX，保存為總位移。時間從 0 開始，啟用推拉。

方向長度近零或 HitPushX=0 時，保持停止。這裡只記下要求，不立即移動角色；新推拉會取代舊推拉。

步驟 3：Tick — 分幀移動受擊者

在 FightingCharacter.cpp 實作 TickHitPush()。未啟用就返回；啟用時依本幀經過的時間，計算這一幀要移動的部分。以下為計算示意，需轉成 C++：

// 這次推拉要在 0.15 秒內完成
Duration = 0.15

// TotalOffset：命中時算好的「方向 × HitPushX」，包含方向與總距離
// OldElapsed：目前已經推了幾秒，開始時設為 0
// DeltaSeconds：這一幀經過的秒數，由 Tick 傳入

// 時間只往前走；Max 表示取兩者較大值，避免使用負時間
FrameSeconds = Max(DeltaSeconds, 0)

// 累加這一幀的時間；Min 表示取較小值，最多算到 0.15 秒
NewElapsed = Min(OldElapsed + FrameSeconds, Duration)

// 最後一幀可能只剩一點時間，因此只計算尚未完成的部分
UsedSeconds = NewElapsed - OldElapsed

// 本幀佔總時間多少比例，就移動總位移的多少比例
FrameOffset = TotalOffset × (UsedSeconds ÷ Duration)

// 保存進度，下一幀從這裡繼續
OldElapsed = NewElapsed

例如要在 0.15 秒內推遠 60 公分，這一幀經過 0.015 秒，就要求移動 60 × (0.015 ÷ 0.15) = 6 公分。若已經過 0.145 秒，即使下一幀又經過 0.015 秒，也只補剩下的 0.005 秒，也就是 2 公分，避免推過頭。以上距離是假設途中沒有碰到阻擋。

以帶 Sweep 的 AddActorWorldOffset 套用 FrameOffset，移動受擊角色的根膠囊。碰到阻擋或時間到達 Duration 就呼叫 EndHitPush；受阻時實際距離可較短。受擊動畫會清除速度，因此這裡使用獨立推拉進度。

步驟 4：End — 停止並清除狀態

在 FightingCharacter.cpp 實作 EndHitPush()：停用推拉、將經過時間與總位移歸零。保留角色已移動的位置，不送回起點。 到期、碰撞、被新推拉取代與角色 EndPlay 都使用同一個清理方法。

步驟 5：接入遊戲並測試

  1. 在 TryApplyHit() 取得 ApplyDamage() 的實際扣血量後，只有 Deducted > 0 才呼叫受擊角色的 InitHitPush，傳入本次 HitPushX 與攻擊者位置。值為 0 也要呼叫，才能停止舊推拉。
  2. 在角色既有 Tick 的 UpdateReaction() 之後、RefreshOpponentDirection() 之前呼叫 TickHitPush；EndPlay 在交給父類之前呼叫 EndHitPush。保留原本去重與受擊反應流程。
  3. 建置、重新載入 Editor、匯入 CSV 後，以 -60、30、0 各測一次。確認負推正拉、0 不推拉、防禦不產生新推拉；再換邊與靠牆測試方向及碰撞。

二、Shake：讓命中觸發鏡頭震動

本題必須新增獨立的 FFightingCameraShake，由 FFightingCameraDirector 持有與管理。

步驟 1：定義資料與介面

  1. 在 Fighting/Camera/CombatCameraShot.h 新增 Shake=2，保留既有 enum 數值。Command CSV 的招式設定留到步驟 5 建置後匯入。
  2. 新增 Fighting/Camera/FightingCameraShake.h/.cpp。在 Shake 類別的 private 區定義啟用狀態、經過時間、時長 0.15 秒、振幅與頻率；public 區宣告 Init()、Tick(DeltaSeconds)、End()、GetLocalOffset() const，供 Director 呼叫。
  3. 在角色保存私有震動事件序號，初值為 0，提供公開唯讀 getter。在 Fighting/Camera/FightingCameraTypes.h 的 FFightingCameraFrameInput 加入玩家與 CPU 的序號欄位。
  4. 在 Fighting/Camera/FightingCameraDirector.cpp include Shake 的 header，並於 FFightingCameraDirector::FImpl 保存一個 Shake 物件與雙方已觀察序號。計時與公式留在 Shake，不在 Director 再存一份。

步驟 2：Init — 啟動一次震動

在 FightingCameraShake.cpp 實作 Init()：先呼叫 End 清除舊效果，再設為啟用，時間從 0 開始。新的命中會重新開始一次 0.15 秒震動。

步驟 3：Tick — 推進時間與提供偏移

在 FightingCameraShake.cpp 實作 Tick()：未啟用就返回；否則累加非負的 DeltaSeconds，最多累加到 0.15 秒，時間到呼叫 End。暫停時不推進。

同檔案實作 GetLocalOffset()，依目前時間算出本地偏移；未啟用時回傳零向量。這個方法只讀取結果，不再次推進時間。 算法與 Director 的合成位置如下：

T = 0.15                    // 總時間，秒
t = Clamp(Elapsed, 0, T)     // 這次震動已經過的遊戲時間
A = 2.0                     // 初始振幅，公分
f = 20.0                    // 每秒擺動次數，Hz
Fade = 1 - t / T
Offset = A × Fade × Sin(2 × PI × f × t)
LocalShakeOffset = (0, Offset, 0)

Sin 讓偏移左右來回，Fade 讓幅度逐漸減小。最後的向量以相機本地座標表示，沿相機右方向移動；2 公分與 20 Hz 是調校起點，可調整到明顯但不影響觀察戰鬥。

以下先說明偏移如何使用，Director 的接入程式留到步驟 5 再加入：在 FFightingCameraDirector::FImpl::EvaluatePose() 完成原有構圖混合後，將本地偏移轉為世界方向，再加入本幀結果。採位置震動，保留 BoomRotation 不變：

// Result 是本幀原有構圖混合完成的結果
WorldShakeOffset = Result.BoomRotation.RotateVector(Shake.GetLocalOffset())
Result.FocusLocation += WorldShakeOffset
// 保留原有 SanitizePose 檢查，然後回傳 Result

只有震動啟用時才加上偏移。FightingCameraActor 繼續透過原有 ApplyPose() 套用結果，不另外保存震動計時或重算公式。不要把偏移反覆加到上一幀結果。 每幀的 FocusLocation 都從角色位置與原有構圖重新算起，時間到就回到原本構圖。

震動只影響最終觀看位置，不改角色座標；避免把震動後的姿態回送為下一幀構圖或角色移動方向的基準。暫停時 DeltaSeconds=0，震動時間也應停止。上述數值是設計範例，仍須實際播放調校。

步驟 4：End — 清除震動效果

在 FightingCameraShake.cpp 實作 End()：停用效果、將經過時間歸零，讓 GetLocalOffset 回傳零向量。Director 下次合成就回到原構圖，不必保存舊相機位置再搬回去，也不要重設角色的事件序號。

步驟 5：接入命中、Director 並測試

  1. 在 TryApplyHit() 通過命中檢查、加入命中集合後，且防禦分支返回前，只有本招選了 Shake 才增加事件序號。此處不等待扣血，所以防禦命中也會觸發。
  2. 在 FightingCameraActor::BuildFrameInput() 收集雙方序號，傳給 Director。Director.Initialize 記住初始序號並呼叫 Shake.End；Update 發現新序號就 Shake.Init，沒有新事件則 Shake.Tick。同幀兩人都觸發時只重啟一次。
  3. 在 Director 的 EvaluatePose 完成原構圖混合後，依步驟 3 的方式合成 Shake.GetLocalOffset。CameraActor 仍只透過 ApplyPose 套用結果。
  4. 調整 GetActiveCameraShotRequest()，讓 Shake 不走整招持續的主構圖請求，保留 UpperBodyCloseUp 原流程，避免揮空也震動。
  5. Command CSV 選一招設為 CameraShot=Shake，另保留一招 UpperBodyCloseUp。建置、重新載入 Editor 並匯入 Command CSV，測試揮空、正常命中、防禦與零傷害命中。確認 0.15 秒後回復，原有特寫仍正常，再完成下方三項展示。
