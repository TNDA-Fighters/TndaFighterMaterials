TNDA Week 03 課前預習｜相對方向與自動面向

課前先完成環境確認與兩組實作，帶著紀錄進入課堂。

本週目標課前準備課前實作 1｜讓 1P 與 CPU 可以重疊（30 分鐘內）課前實作 2｜把換邊流程分成 Gameplay 與 ABP（30 分鐘內）教材專案內要使用的文件官方參考資料上課前確認

本週目標

從碰撞、相對方向與動畫表現三個角度讀懂教材專案，理解角色為什麼不會重疊，以及角色換邊後如何維持正確方向並平順轉身。

課前準備

  • 使用本週提供的 TndaFighter 教材專案。
  • 確認 /Game/Fighting/stage1 能進入 PIE，1P 與 CPU 都會出現。
  • 操作前先用 GitHub Desktop 確認工作目錄狀態，避免覆蓋自己的其他修改。

課前實作 1｜讓 1P 與 CPU 可以重疊（30 分鐘內）

給學生看的題目

先記錄 1P 與 CPU 的根 Capsule 碰撞設定，以及兩者接觸時的畫面。只調整教材專案中既有的碰撞設定，嘗試讓 1P 能進入並穿過 CPU 的位置。留下修改前後的設定與 PIE 畫面，完成後恢復原始設定。

要帶來上課的紀錄

  • 1P 與 CPU 根 Capsule 的原始碰撞設定。
  • 你修改的物件、設定名稱與修改值。
  • 修改前無法重疊，以及修改後可以穿過的對照畫面。
  • 一句話說明原本是哪個元件阻止兩名角色疊在一起。

課前實作 2｜把換邊流程分成 Gameplay 與 ABP（30 分鐘內）

給學生看的題目

閱讀教材專案內的「換邊與自動面向」架構流程文件，把 Opponent Reference、戰鬥軸、4／6 相對方向、目標面向、旋轉插值與 ABP Pose 分到 Gameplay 與 Animation Blueprint 兩個責任區。畫一張雙泳道流程圖，標出資料從角色位置一路到畫面姿勢的方向。

要帶來上課的紀錄

  • 一張 Gameplay／Animation Blueprint 雙泳道流程圖。
  • 每個指定概念所在的責任區與一句理由。
  • 一個你認為最不應該交給 ABP 決定的項目，以及理由。

教材專案內要使用的文件

  • 教材專案 docs/為何 1P 與 CPU 不會疊在一起呢.md。
  • 教材專案 docs/ 內的「換邊與自動面向」架構流程文件。
  • 教材專案 docs/blueprints/ABP_Manny_Combat.md。

官方參考資料

  • Epic Games：Collision Overview：說明 Block、Overlap、Ignore 之間的互動規則。
  • Epic Games：Collision Response Reference：整理 Collision Preset、Collision Enabled、Object Type 與 Collision Response 等設定。
  • Epic Games：Graphing in Animation Blueprints：說明 EventGraph 與 AnimGraph 如何共同產生角色的最終 Pose。
  • Epic Games：State Machines：說明 Animation Blueprint 內的 State、Transition 與輸出 Pose。
  • Epic Games：RInterp To：說明如何依目前旋轉、目標旋轉、Delta Time 與 Interp Speed 計算平順旋轉。

上課前確認

  • 已記錄 1P 與 CPU 的原始碰撞設定。
  • 已讓 1P 在 PIE 中進入並穿過 CPU 的位置。
  • 測試後已恢復原始碰撞設定。
  • 雙泳道流程圖已包含題目指定的六個概念。
  • 能用自己的話區分 Gameplay 邏輯與 ABP Pose。
