UE5 Collision：先分清啟用模式、類型與回應

① Collision Enabled

決定形狀參與哪些工作：空間查詢、物理模擬，或兩者都參與。

② Object Type

標示「我是誰」，例如 Pawn、WorldStatic；本專案另外定義 Hitbox 與 Hurtbox。

③ Collision Responses

設定碰撞回應：Ignore 忽略、Overlap 重疊、Block 阻擋。這裡的 Overlap 是回應設定，還不是查詢或事件。

模式決定參與什麼；通道與回應決定如何互動

Hitbox ↔ Hurtbox 設為 Overlap 回應。設定好參與方式後，下一步才是：程式如何主動查詢接觸？ Epic：Collision Overview ↗

程式定位｜Config/DefaultEngine.ini · Hitbox／Hurtbox Profile（欄位摘錄）
Hitbox:  ObjectTypeName="Hitbox";  Hurtbox → ECR_Overlap
Hurtbox: ObjectTypeName="Hurtbox"; Hitbox → ECR_Overlap
其餘 Pawn／WorldStatic／Camera 等回應為 Ignore；這些是命中形狀，不是角色移動膠囊。

和 AI 協作：把「從動畫重建碰撞」寫進規格

# 目標
為 UE5 格鬥遊戲實作「從動畫姿勢重建攻擊球」的連續命中判定。

## 必要實作
1. 依 Montage 時間抽取骨骼姿勢，套用附掛偏移，保存局部姿勢樣本。
2. 每幀裁切前後進度與 Active 的交集，補出中間姿勢，再套當時 Mesh 世界位姿。
3. 保留攻擊球半徑，將對手 Hurtbox 膠囊對齊同一世界時間，做移動形狀求交。
4. 命中候選通過對手、部位與同拳去重檢查後，才依 Damage ID 查表扣血。

## 限制與驗收
- 不能只靠 OnComponentBeginOverlap 或目前 Socket；不以放大球、延長 Active 補救。
- 長幀穿過要能補查；揮空不誤中；同拳只扣一次，下一拳可以再命中。

## 請先回覆
先查現有實作，再說明資料結構、重建／求交流程、取樣成本與支援限制；缺少資訊請指出。
