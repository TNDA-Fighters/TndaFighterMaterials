課前準備

使用 week-07 教材專案，確認能開啟 /Game/Fighting/stage1。本週的 X、Y 是攻擊語意；交付鍵位 U 對應 X、I 對應 Y。數字 6 表示水平方向朝向對手，4 表示遠離對手，並非鍵盤數字鍵。UE 距離單位採 cm。先確認兩個角色可正常出現，再閱讀下面兩條流程。

課前預習

課前預習 1｜招式資料怎麼決定哪個判定部位在何時可用？

先分清三個責任。 Hitbox 是攻擊者附在骨骼上的球形判定；Hurtbox 是對手附在骨骼上的膠囊判定。Active 是動畫中可以產生命中候選的時間區間。拳頭看起來碰到對手，仍須符合時間、空間與招式規則。

資料路徑。 從 _DataTable/CommandTable.csv 的 ID 2 開始：Keys=6,X、Hitbox=foot_r、Hurtboxes=head。在 Source/TndaFighter/DataTable/TndaCommandData.h 找 FTndaCommandRow 與 FTndaCommand；再讀 DataTable/TndaCommandReader.cpp::Prepare()，看 ParseHitbox()／ParseHurtboxes() 如何整理 token。角色選招後保存 CurrentAttack 副本。最後到 Fighting/FightingCharacter.cpp::BeginActiveHitbox()，它以 CurrentAttack.Hitbox 找出既有元件；部位不是從動畫名稱猜出來的。

時間路徑。 開啟 /Game/Fighting/Anims/AM_Attack_03 的 Damage Notify State。引擎播放跨入／離開區間時呼叫 Source/TndaFighter/Fighting/FightingDamageNotifyState.cpp::NotifyBegin()／NotifyEnd()，再呼叫角色的 BeginActiveHitbox()／EndActiveHitbox()。引擎對 Notify 的呼叫是框架事件，CSV 整理與角色開關則是專案程式。Notify 不保存扣血值或骨骼名。

元件在 Active 時切到 QueryOnly，供狀態與除錯觀察；正式扣血由動畫姿勢軌跡產生候選，再走下一條流程。不要把此版本教成 OnComponentBeginOverlap 直接扣血。

練習使用的 Y 招式。 Command ID 3 是 Y（按 I），使用 AM_Attack_02、左手 Hitbox hand_l，並指向 Damage ID 3。交付基準的 Hurtboxes 是 "head,pelvis,calf_l,calf_r"，代表頭部、骨盆與左右小腿都是允許結算的受擊部位；它不是攻擊者的骨骼清單。只留下 "head" 時，身體接觸會被規則排除，但動畫與左手軌跡不變，仍須真的碰到頭部才會命中。

課前預習 2｜一次命中後，傷害如何查表並扣到對手生命值？

先分清 ID 與數值。 Command 的 Damage=1 表示查 Damage 表 ID 1，不代表扣 1 點。_DataTable/DamageTable.csv 的 ID 1 才保存 Damage=10。HP 是執行期剩餘生命值；MaxHealth 是新一輪開始時的上限。

沿著候選走到扣血。 在 Source/TndaFighter/Fighting/FightingCharacter.cpp 依序讀 HandleWorldPostActorTick()、ProcessFrameAttack()、TryApplyHit()、EvaluateHitRule()。正式候選先受 Montage 的 Damage 區間與連續軌跡限制；TryApplyHit() 再檢查是否仍在攻擊、是否為唯一對手、接觸的 Hurtbox 是否在允許清單、是否已在 HitCharacters。通過後才呼叫 Source/TndaFighter/DataTable/TndaDamageReader.cpp::TryGetDamage()，以 CurrentAttack.DamageId 在結算當下取得傷害。

終點是 Source/TndaFighter/Fighting/FightingHealthComponent.cpp::ApplyDamage()。實際扣除量是 Clamp(Damage, 0, CurrentHealth)，所以 20 HP 遇到 33 傷害只扣 20，剩餘 HP 為 0；0 傷害合法，但不減血。BeginPlay() 會呼叫 ResetToMaxHealth()，新開 PIE 會回滿血。

HitCharacters 保存本次揮擊已命中的角色；碰到對手多個 Hurtbox 也不會重複結算。FinishAttack() 在結束或中斷時清空集合。Command 保存 Damage ID，扣血數字在命中當下查；Reimport 不會追溯改寫已扣掉的 HP。

看懂除錯顯示與防禦。 在 PIE 控制檯使用 tnda.Debug.ShowCombatDebug on|off，可切換 Hurtbox、Active Hitbox、命中部位標記與雙方 HP 顯示；命中部位會短暫標紅並標名。這個指令改變的是除錯顯示。tnda.Debug.CpuAlwaysDef on|off 則改變目前配對 CPU 面對 1P 有效命中時的結算：開啟後播放防禦反應，不扣 HP；關閉後，後續有效命中恢復一般傷害結算。兩個指令也接受 1|0，作用於本次執行期，不會改寫 Blueprint 或 CSV。沒有扣血可能是沒有命中、被防禦，或傷害為 0，必須連同畫面與資料判讀。

課前實作練習

課前實作練習 1｜讓第二攻擊只命中頭部，並調整命中傷害

使用 tnda.Debug.ShowCombatDebug 顯示命中部位與 HP，先以基準 Y 招式（按 I）展示命中身體的結果。只把 _DataTable/CommandTable.csv 的 ID 3 Hurtboxes 從 "head,pelvis,calf_l,calf_r" 改為 "head"，儲存並 Reimport DT_Command，做出身體接觸不再結算、接觸頭部才標示 head 並扣血的版本。只允許頭部不會改變招式軌跡，請找到能命中頭部的位置與距離。

再只把 _DataTable/DamageTable.csv 的 ID 3 Damage 從 20 改為 33，儲存並 Reimport DT_Damage。在 CPU 剩餘 HP 足夠的情況下，展示頭部命中由扣 20 改為扣 33。保留 Command 的 Damage ID、Hitbox、指令、動畫、Notify、其他資料列與 Blueprint 設定，並保持 CPU 強制防禦關閉。

上課時遠端展示兩張資料表、改動前後的命中部位與 HP，用自己的話說明：Hurtboxes 與 Damage 各決定什麼？為什麼只允許 head 後，碰到身體不再扣血？這是否代表每次出招都一定命中頭部？驗收後還原兩張表的基準資料與除錯狀態。

課前實作練習 2｜用除錯指令看懂命中與防禦

在 PIE 使用 tnda.Debug.ShowCombatDebug 開啟判定與 HP 顯示，並用 tnda.Debug.CpuAlwaysDef 切換 CPU 強制防禦。在同一個可命中的距離，用 X（按 U）分別展示一般命中與強制防禦的結果，觀察 Active Hitbox、Hurtbox、CPU 反應與 HP；再關閉強制防禦，展示後續命中恢復扣血。保留 CSV、DataTable、Blueprint 與 Notify 設定。

上課時遠端分享桌面，自己操作並用自己的話說明：兩個指令各改變了什麼？看到判定接觸，是否就代表一定扣血？你從哪些畫面或 HP 變化判斷這次是命中扣血、被防禦或沒有命中？驗收後還原除錯狀態。

官方參考資料

  • Collision Overview：先讀 Object Type、Block／Overlap／Ignore 與 Generate Overlap Events，分清碰撞回應和事件通知。
  • Collision Response Reference：對照元件的 Collision Presets、Object Type 與 Collision Enabled；重點閱讀 Query Only，理解空間查詢與物理模擬的差別。
  • Traces Overview：延伸閱讀線段與形狀軌跡查詢，建立沿路徑找接觸對象的概念。本週教材的正式命中採動畫姿勢軌跡與專案規則結算，不能直接把官方 Trace 範例或 Overlap 事件當成專案的扣血流程。
  • Data Driven Gameplay Elements：DataTable 與列結構概念。
  • Animation Notifies：Notify State 的開始與結束事件。
  • Animation Montage：Montage 與動畫播放設定。
