課前預習

課前預習 1｜A／D、4／6 與相對方向通知

先分清按鍵和方向代號

在本週的格鬥視角中，A 讓角色朝螢幕左方移動，D 朝螢幕右方移動。角色換邊後，這組按鍵方向仍然相同。

4、6 是相對於對手的方向代號：4 表示後退，也就是遠離對手；6 表示前進，也就是靠近對手。因此，同一個按鍵會隨站位得到不同的方向代號。

1P 在螢幕上的位置 A：朝螢幕左方 D：朝螢幕右方
1P 在 CPU 左側 遠離對手，4 靠近對手，6
1P 在 CPU 右側 靠近對手，6 遠離對手，4

程式以列舉 ERelativeDirection 表示三種結果：Backward4、Forward6、Neutral（中立）。4／6 描述的是輸入意圖；即使角色被擋住，朝向對手的輸入仍可判為 6。放開移動鍵後，目前方向會回到 Neutral。

從移動輸入到方向通知

以下路徑已依本週原始碼核對。追蹤從玩家的 DoMove() 開始，到方向通知送出為止。

  1. FightingPlayerCharacter.cpp 的 DoMove(Right, Forward) 使用攝影機的水平旋轉，將左右、前後兩個輸入軸合成世界移動方向 MovementIntent。這是本次想往哪裡走。
  2. 同一個函式呼叫共同父類的 TryGetOpponentDirection()。它在 FightingCharacter.cpp 讀出 LastValidOpponentDirection，代表由自己指向對手的有效水平方向；資料如何更新，接著在預習 2 追蹤。
  3. FightingCharacter.cpp 的 ClassifyRelativeDirection() 比較這兩個方向，回傳 ERelativeDirection。取得不到有效對手方向時，DoMove() 直接使用 Neutral。
  4. 回到 FightingPlayerCharacter.cpp 的 SetCurrentRelativeDirection()：新值與目前值不同時，先更新 CurrentRelativeDirection，再呼叫 OnRelativeDirectionChanged.Broadcast(CurrentRelativeDirection)，將新值通知已綁定的接收者。值相同就結束這次呼叫。

OnRelativeDirectionChanged 是多播委派（Multicast Delegate）：其他物件可以綁定處理函式，Broadcast() 會通知這些接收者。本週保存的是目前方向，沒有歷史輸入佇列。

按住移動鍵時，SetupPlayerInputComponent() 綁定的 Triggered 會持續呼叫 Move()，再進入 DoMove()。所以角色穿過對手後，即使沒有放開同一個鍵，也可能產生新的 4／6。放開或取消輸入時，則由 StopMove() 將目前值設回中立。

用教材的 Debug 顯示對照結果

在 PIE 遊戲畫面按 ~ 開啟 Console，輸入 tnda.Debug.ShowCombatDebug on 後按 Enter，再收起 Console，就能用 A／D 對照目前方向。畫面文字會把 Forward6 顯示為 Forward 6，把 Backward4 顯示為 Backward 4。

畫面標記 代表的資料
玩家上方小球 綠色為 6、紅色為 4、灰色為中立。
綠色箭頭 玩家指向對手的最後有效方向。
藍色箭頭 目標面向 DesiredFacingYaw；目前轉到哪裡要看角色本身。
黃線、青色球、洋紅色箭頭 分別表示雙方連線、戰鬥中點、攝影機的螢幕 X 軸。

繪製程式位於 FightingPlayerCharacter.cpp 的 DrawCombatDebug()，顯示的是角色已有的資料。

課前預習 2｜從共同角色 Tick 找到自動面向的可調參數

兩個角色共用哪些程式

Source/TndaFighter/Fighting/FightingPlayerCharacter.h 與 Source/TndaFighter/Fighting/FightingCpuCharacter.h 的類別宣告，都繼承 AFightingCharacter。1P 和 CPU 因此共用對手方向與自動面向的實作，各自保有自己的設定值。

這次從 Source/TndaFighter/Fighting/FightingCharacter.cpp 的 AFightingCharacter::Tick() 開始，對照同目錄 FightingCharacter.h 的欄位宣告。Tick() 是引擎每幀呼叫的更新入口；兩個角色自己的 Tick() 都透過 Super::Tick(DeltaSeconds) 執行父類邏輯。

每幀如何轉向對手

以下是已核對的 C++ 呼叫與資料流。主要路徑是一般地面狀態下，已有有效對手方向時的更新。

  1. FightingCharacter.cpp 的 Tick() 依序呼叫 RefreshOpponentDirection() 與 UpdateFacing(DeltaSeconds)。DeltaSeconds 是這次更新經過的秒數。
  2. RefreshOpponentDirection() 將雙方位置交給 UpdateHorizontalOpponentDirection()，更新 LastValidOpponentDirection。後者只保留水平分量並將向量長度變成 1，讓這份資料只描述方向。
  3. 有效方向透過 LastValidOpponentDirection.Rotation().Yaw 轉成目標角度 DesiredFacingYaw。Yaw 表示角色在水平面上朝向哪裡。
  4. UpdateFacing() 讀取目前的 GetActorRotation()，以 DesiredFacingYaw 組出目標旋轉。它依 bShouldSnap 選擇立即套用，或交給 FMath::RInterpTo() 逐幀追向，最後由 SetActorRotation() 寫回角色旋轉。

這張圖畫的是平順轉身的分支。首次有效面向會直接對正；雙方水平距離不大於 10 公分時，方向資料沿用最後有效值。還沒有有效方向時保留原旋轉。IsInNormalGroundState() 也會檢查角色是否在地面、是否正在播放 Montage 或使用 Root Motion；不符合時暫停寫入角色旋轉。

從 C++ 宣告找到編輯器欄位

FightingCharacter.h 中有這段宣告：

UPROPERTY(EditAnywhere, BlueprintReadOnly, Category = "Fighting Character|Facing", meta = (ClampMin = "0.0"))
float FacingInterpolationSpeed = 10.0f;
  • FacingInterpolationSpeed 控制追向目標角度的速度。C++ 原生預設值為 10，Blueprint 可以覆寫；正值越小，追向越慢。特殊值如何處理，可以對照 UpdateFacing() 裡的 bShouldSnap 條件。
  • EditAnywhere 讓屬性能在預設值與執行個體的 Details 編輯。BlueprintReadOnly 則限制 Blueprint 圖表對此值的寫入，兩者管的是不同的操作。
  • Category 指定欄位放在 Fighting Character > Facing；編輯器顯示名稱為 Facing Interpolation Speed。

對應的角色 Blueprint 是 /Game/Fighting/Blueprints/BP_FightingPlayerCharacter 與 /Game/Fighting/Blueprints/BP_FightingCpuCharacter。Class Defaults 決定之後生成角色的起始設定；PIE 執行個體則是這次遊戲裡已生成的那一名角色。

比較面向時，分開看三件事：DesiredFacingYaw 是想朝向哪裡，Actor Rotation 是目前轉到哪裡，FacingInterpolationSpeed 是追向速度。前兩者在轉身期間可以不同。

換邊測試工具
