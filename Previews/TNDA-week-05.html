本週目標

  • 用 Xbox 搖桿操作移動與出拳，說明實體按鍵如何經過 Enhanced Input 接到 C++。
  • 分清動畫片段、Montage 與 Slot 的用途，找到角色使用的攻擊動畫設定。
  • 追到攻擊結束通知，說明角色何時恢復移動與再次出招的資格。
  • 完成兩個可還原的設定練習，於課堂分享桌面、實際操作並口頭說明。

課前準備

使用講師提供的 TndaFighter week-05 教材（44e6c65）與 UE 5.8。開啟 /Game/Fighting/stage1；本週已包含搖桿十字方向鍵移動、X 出拳，以及鍵盤 U 的同等攻擊操作。出拳成功以動畫播放為準，尚未加入命中、扣血或連段。

準備可被 Windows 辨識的 Xbox 搖桿，並確認能在 PIE（Play In Editor，編輯器內執行遊戲）操控角色。課堂需分享 UE 畫面、設定與 Output Log，不必另交截圖或測量紀錄。四向操作與出拳先使用教材原始設定測試，兩項練習各自從原始設定開始。

本頁的 Source/... 路徑以教材專案根目錄為起點；/Game/... 是 Content Browser 的資產路徑，例如 /Game/Fighting/Anims/AM_Attack_01 對應 Content/Fighting/Anims/AM_Attack_01。

課前預習

課前預習 1｜從 Xbox 搖桿找到移動與出拳的程式入口

先用原始設定確認操作

綠框的十字方向鍵控制移動，紅框的 X 按鈕觸發攻擊。先確認上、下、左、右都能移動，放開後會停下；再按 X 出拳，長按不連發。放開 X 並等這次攻擊完整結束，再按一次，應能再次出拳。測試時離開牆面和另一個角色，避免把碰撞阻擋誤認為輸入失效。圖片由講師提供。

同一個 X，可能是在說不同東西

名稱 本週代表什麼
搖桿 X 按鈕 實體按鈕，在 UE 的 Key 名稱是 Gamepad_FaceButton_Left。
攻擊語意 X 程式收到的招式名稱，命名沿用搖桿 X；鍵盤 U 也送出這個名稱。
二維輸入的 X 軸 IA_Move 的左右數值，與攻擊名稱無關；Y 軸是前後數值。
4／6 方向 相對對手的遠離／靠近，不是十字方向鍵本身的名稱。

Input Mapping Context（IMC）是按鍵對應表，Input Action（IA）代表遊戲收到的動作。Modifier 會調整輸入值，例如交換軸向或反轉正負。這些資產先產生輸入資料，C++ 再決定角色如何反應。

IA_Move 使用二維向量；IA_Attack1 使用 Boolean，表示按下與放開。不要把「Boolean 動作」當成 bIsAttacking：前者是輸入，後者是角色已接受攻擊後的狀態。

按鍵到動作的資料變化

十字方向鍵 UE Key IA_Move 數值（左右，前後） Modifier
上 Gamepad_DPad_Up (0, 1) SwizzleAxis：YXZ
下 Gamepad_DPad_Down (0, -1) SwizzleAxis：YXZ、Negate
左 Gamepad_DPad_Left (-1, 0) Negate
右 Gamepad_DPad_Right (1, 0) 無

這些方向以目前攝影機的水平朝向為基準，不是世界座標固定的正 X、正 Y。搖桿 X 與鍵盤 U 則都對應 /Game/Fighting/Input/Actions/IA_Attack1，再由 C++ 送出名稱 X。

閱讀路徑 A：共同輸入設定與移動分支

  1. 從 Source/TndaFighter/Fighting/FightingPlayerController.cpp 的 AFightingPlayerController::SetupInputComponent() 開始。它將 DefaultMappingContexts 逐一交給本機玩家的 AddMappingContext()，讓按鍵對應表生效。
  2. 到 Source/TndaFighter/Fighting/FightingPlayerCharacter.h 看 MoveAction、AttackAction 宣告，再到同名 .cpp 的 SetupPlayerInputComponent()。BindAction() 將 IA、事件種類及接收函式綁在一起。
  3. 沿同檔的 Move() → DoMove() 往下看。Move() 取出 FVector2D，DoMove() 取得攝影機水平方向、換算移動意圖並更新 4／6；符合操作條件時，終點是 AddMovementInput()。此處只讀資料怎麼傳，不重算前幾週的方向公式。
  4. 找 StopMove()：它綁在 Completed／Canceled，清除保存的推擠意圖，並把相對方向設回 Neutral。實際減速與停止仍由移動系統處理。

閱讀路徑 B：出拳分支到角色的 Montage 設定

  1. 在同一個 SetupPlayerInputComponent() 找 AttackAction：攻擊綁的是 Started，接到 AFightingPlayerCharacter::Attack()。
  2. Attack() 呼叫 TryExecuteCommand(TEXT("X"))。TEXT("X") 表示文字 X；參數型別 FName 用來保存這個名稱。AFightingPlayerCharacter::TryExecuteCommand() 先檢查 Controller，再以 Super::TryExecuteCommand() 呼叫父類版本；Super:: 就是「交給父類處理」。
  3. 到 Source/TndaFighter/Fighting/FightingCharacter.cpp 的 AFightingCharacter::TryExecuteCommand()。這是玩家與 CPU 共用的攻擊入口，先檢查語意、狀態、對手與動畫設定，才呼叫 Montage_Play()。
  4. 最後到 Source/TndaFighter/Fighting/FightingCharacter.h 找 BasicAttackMontage，再對照 /Game/Fighting/Blueprints/BP_FightingPlayerCharacter 的 Class Defaults。EditDefaultsOnly 表示在類別預設值設定，這題不改 PIE 執行個體；教材 BP 指向 /Game/Fighting/Anims/AM_Attack_01。

這裡有三種動畫名詞：AnimSequence 是原始動作資料，本週用 MM_Attack_01；Montage 安排怎麼使用及播放片段，本週用 AM_Attack_01；Slot 是 Montage 進入 AnimGraph 的接點，本週是 DefaultGroup.DefaultSlot。角色 BP 保存 Montage 參照，C++ 讀取參照後啟動播放。

這兩個分支的 C++ 呼叫與綁定已核對 week-05 原始碼。硬體輸入經 Enhanced Input 呼叫綁定函式，是引擎負責的串接；資產對應及 Slot 配置依教材已有的 MCP 查證紀錄。本週預習不要求新增 Blueprint 接線，也不追引擎內部的輸入實作。

課前預習 2｜攻擊何時結束，角色何時能再次移動？

先分清播放、混合與通知

  • Play Rate 是播放倍率。片段設為 0.5，該片段以半速播放；它不會自動把整個世界一起放慢。
  • Blend In／Blend Out 是從原姿勢進入攻擊、再退出攻擊姿勢的混合過程。開始淡出不等於攻擊已完整結束。
  • Callback（回呼）是事件發生時，系統回頭呼叫我們登記的函式。這裡登記的是 Montage 結束通知。
  • bIsAttacking 是攻擊鎖定狀態；CurrentCommand 是本次已接受的招式名稱。它們都是執行時唯讀觀察欄位，不是練習用的開關。

閱讀路徑：播放成功到恢復操作

  1. 從 Source/TndaFighter/Fighting/FightingCharacter.cpp 的 TryExecuteCommand() 接續預習 1。找到 Montage_Play() 的結果與當次播放實例檢查。只有播放成功，才保存 CurrentCommand 並將 bIsAttacking 設為 true。
  2. 找 Instance->OnMontageEnded.BindUObject(...)。它把這次播放的結束通知綁到 HandleAttackEnded()；-> 表示透過物件指標存取成員。此處只需辨認「誰的通知、交給誰處理」，不展開指標管理。
  3. 到同檔 HandleAttackEnded()。它確認通知屬於目前這次播放，再呼叫 FinishAttack(false)。後者清除播放身分、將 bIsAttacking 設回 false，並把 CurrentCommand 清為 None。
  4. 對照 Source/TndaFighter/Fighting/FightingPlayerCharacter.cpp 的 DoMove()：方向語意先更新，再檢查 bIsAttacking。攻擊中提前返回，不送出 AddMovementInput()；收尾後若仍按住方向，下一次 Triggered 就能沿正常路徑移動。已經放開的方向不會由收尾函式補送。
  5. 最後對照玩家 PIE 執行個體中的 Is Attacking 與 Current Command。有效攻擊期間預期是 true／X，完整收尾後是 false／None；用操作結果一起判讀，不只看動畫似乎停了。

本週先讀到這裡

正常結束與取消後的淡出都要完整收尾。失去對手、播放者重建及關閉世界的保護流程留在課堂與教師補充。本週也沒有「把攻擊中按過的 X 排隊，解鎖後補播」的機制。

課前實作練習

課前實作練習 1｜讓缺少 Montage 的角色拒絕攻擊，仍可正常移動

只調整 /Game/Fighting/Blueprints/BP_FightingPlayerCharacter 的 Class Defaults，把 BasicAttackMontage 清為 None，編譯並儲存。先依預習路徑預測按下 X 後的結果，再親自操作驗證。

課堂分享桌面時，展示儲存的設定；在 stage1、對手有效且角色正常站在地面時，按搖桿 X 應沒有出拳。Output Log 要看得到包含 command=X、montage=None 與 reason=invalid animation configuration 的 Warning，角色仍能用十字方向鍵移動。鍵盤 U 與方向鍵可作對照，不能取代實體搖桿確認。

口頭說明：哪個函式拒絕了這次攻擊，為什麼角色沒有被鎖住？修改只限玩家 BP 的 Montage 參照，不改 CPU、C++ 或其他輸入設定。完成展示後能還原原始參照；下一題從已配置 AM_Attack_01 的狀態開始。

課前實作練習 2｜做出慢速攻擊，讓操作鎖定跟著播放結束

在角色已配置 AM_Attack_01 的前提下，把 /Game/Fighting/Anims/AM_Attack_01 內 MM_Attack_01 片段的 Play Rate 從 1 改成 0.5 並儲存，做出較慢的單次攻擊。先用預習的回呼路徑預測解鎖時機，再用實際操作驗證。

課堂分享桌面時，展示片段的新倍率及 PIE 操作：攻擊完整結束前仍不能主動移動或重啟攻擊；結束後，持續按住的方向輸入恢復移動，放開並再次按下 X 也能重新出招。

只改 Montage 片段的 Play Rate，保留完整片段、Loop Count 1、Slot、單一非循環 Section 及 Auto Blend Out。不要修改原始 AnimSequence、C++、Blend In／Out 或狀態欄位。

口頭說明：動作變慢後，哪個通知讓角色恢復移動，而不是固定等一秒？完成展示後能還原 Play Rate，避免影響課堂的姿勢混合比較。
