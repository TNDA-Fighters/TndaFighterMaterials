課前預習

課前預習 1｜同樣按 X，為什麼能選到不同連段步驟

先分清四個東西

  • 實體按鍵：鍵盤上真的按下的鍵，例如 U。
  • 攻擊語意：程式拿來選招的代號。U 送出 X，I 送出 Y；按著方向時再加上方向數字，例如 6X。4 和 6 是相對於對手的後退與前進，換邊後同一顆方向鍵的數字會對調。
  • Command ID：CommandTable 每一列的編號，也就是 Combat Debug 上 Attack 那一行顯示的 ID。同一個攻擊語意可以對應好幾個 ID。
  • Montage：這個 ID 實際播放的攻擊動畫。不同 ID 可以播同一份 Montage。

本週的五列招式

ID 招式 Keys Montage Damage Link Opener
1 基本攻擊 X AM_Attack_01 1 4,3 空白
2 右腳踢頭 6,X AM_Attack_03 2 空白 空白
3 第二攻擊 Y AM_Attack_02 3 空白 空白
4 連段二段 X AM_Attack_02 3 5 FALSE
5 連段三段 X AM_Attack_01 1 空白 FALSE
  • Link：這一招出招中，下一招可以選哪些 ID。空白代表這一招之後接不了任何招。
  • Opener：這一列能不能在空檔起手。空白或 TRUE 代表可以，FALSE 代表只能靠別人的 Link 接出來。只接受這三種寫法，而且要區分大小寫。

選招的四條規則

  1. 空檔起手只看 Opener。 角色沒在出招時按 X，候選只有 Opener 是空白或 TRUE 的列。ID 4、5 是 FALSE，所以空檔按 X 一定是 ID 1。
  2. 連段中只看 Link。 角色出招中按 X，候選只有目前這一招 Link 列出的 ID，這時不再看 Opener。ID 1 出招中按 X，候選是 4 和 3；ID 3 的 Keys 是 Y，所以選到 ID 4。
  3. 接招不能接同一份 Montage。 候選的 Montage 和目前這一招相同時，這次輸入會被拒絕。資料表在匯入時也會檢查：Link 指向自己、指向同一份 Montage，或 Link 繞成一圈，整張表都會驗證失敗，PIE 會跳出對話框並停止。
  4. 候選有好幾列時，依固定順序取第一列。 先比 Priority，數字大的先；再比有沒有方向，有方向的先；最後比 ID，小的先。Keys 沒寫方向的列，按任何方向都算符合，所以空檔按 4X 也會選到 ID 1。

X→X→X 怎麼變成 1→4→5

  1. 空檔按 X：依規則 1，選到 ID 1。
  2. ID 1 出招中按 X：依規則 2，候選是 4、3，只有 ID 4 是 X，接出第二段。
  3. ID 4 出招中按 X：Link 只有 5，接出第三段。
  4. ID 5 出招中再按 X：ID 5 的 Link 是空白，沒有候選，這次輸入不會出招。

ID 1 和 ID 5 都播 AM_Attack_01。中間隔著 ID 4，每一步接的都是不同 Montage，所以不違反規則 3。ID 5 的 Link 是空白，連段在這裡結束，不會繞回第一段。

課前預習 2｜幀優勢是在比較誰先恢復

先懂幾個名詞

  • 設計幀：本課把 1 秒切成 60 格，1 幀就是 1/60 秒。下面的幀數都以「這一招開始播放」的那一幀為第 0 幀，也就是 Combat Debug 上 Frame 從 0 開始數的那一幀。
  • 命中幀：攻擊判定第一次碰到對手的那一幀。對手已站在攻擊範圍內時，命中幀就是傷害判定開始的那一幀。
  • 恢復：角色回到 Neutral 或 Defending，可以移動與出招。攻擊方要等整份 Montage 播完才恢復；受擊方要等硬直倒數完才恢復。
  • 硬直：被打中的 Hitstun 與防住的 Blockstun，長度寫在 DamageTable，單位是設計幀。
  • 幀優勢：同一次攻防結束後，誰先恢復、早幾幀。本課一律站在攻擊方看：正數代表攻擊方先恢復，負數代表防守方先恢復，0 代表同時恢復。

三份 Montage 的時間軸（單位：設計幀）

Montage 用到的招式 長度 Preorder 傷害判定 Enable～Disable
AM_Attack_01 ID 1、ID 5 30 2 7～11 15～23
AM_Attack_02 ID 3、ID 4 40 3 10～16 20～28
AM_Attack_03 ID 2 70 6 14～27 32～44

長度 30 代表第 0～29 幀在播放，第 30 幀恢復。Preorder 之後先按的下一招會被記下來，到 Enable 那一幀接出；Disable 之後就接不了。

連段只看最後一段。 先看一個例子：你從空檔連按三次 X，依序出 ID 1 → ID 4 → ID 5。連段的每一段都在前一段的 Enable 那一幀接出，所以先換算每一段的起點；下面的幀數都以第一段的第 0 幀為起點：

段 招式 從哪一幀開始 打到 CPU
1 ID 1 第 0 幀 0＋7＝第 7 幀
2 ID 4 ID 1 的 Enable＝第 15 幀 15＋10＝第 25 幀
3 ID 5 15＋ID 4 的 Enable 20＝第 35 幀 35＋7＝第 42 幀

你在 35＋長度 30＝第 65 幀恢復。CPU 什麼時候恢復，要看它有沒有擋住，但兩種情況都照同一條規則：CPU 還在硬直中又被打到，硬直從這一下重新計時，不會累加。

情況 A：CPU 三段都擋住

段 打到 CPU 原本的 Blockstun 到 新的 Blockstun 改到
1 第 7 幀 無 7＋26＝第 33 幀
2 第 25 幀 第 33 幀，還沒結束 25＋28＝第 53 幀
3 第 42 幀 第 53 幀，還沒結束 42＋26＝第 68 幀

第二段在第 25 幀打到時，CPU 第一段的 Blockstun 要到第 33 幀才結束。硬直中不能移動也不能出招，CPU 沒有空檔反擊或逃開，只能繼續防；第三段也一樣。CPU 第 68 幀恢復，幀優勢是 68－65＝＋3。

情況 B：CPU 三段都被打中

段 打到 CPU 原本的 Hitstun 到 新的 Hitstun 改到
1 第 7 幀 無 7＋29＝第 36 幀
2 第 25 幀 第 36 幀，還沒結束 25＋32＝第 57 幀
3 第 42 幀 第 57 幀，還沒結束 42＋29＝第 71 幀

道理和情況 A 相同：每一段都在上一段的 Hitstun 結束前打到，CPU 一路被鎖在硬直裡。CPU 第 71 幀恢復，幀優勢是 71－65＝＋6。

為什麼不會一段擋住、一段打中？

  • 攻擊序列：角色從空檔起手時，程式會給這次攻擊一個新的序列號；連段中接出的招沿用同一號，整套打完回到空檔才結束。所以 ID 1 → ID 4 → ID 5 是同一個攻擊序列。
  • AI 只對新序列抽一次：一般對戰時（tnda.Debug.CPUDefense auto），CPU 看到對手開始一個新的攻擊序列，才抽一次要不要防。抽到防，整套連段都擋住；沒抽到，或反應太慢讓第一段先打中，這套連段就不會再改成防。
  • 所以整套連段只有兩種結果：一直擋住，CPU 一路 Blockstun；或一直命中，CPU 一路 Hitstun。on／off 是每一下都防／都不防，同樣不會混合。

為什麼只看最後一段？ 把第三段的起點記作 S：CPU 在「S＋7＋硬直」恢復，你在「S＋30」恢復。兩者相減，S 就消掉了，只剩「7＋硬直－30」。所以前面接了幾段、第三段從第幾幀開始，都不影響結果；情況 A、B 的答案分別和單發 X 被防的 ＋3、打中的 ＋6 相同。

公式： 整套連段的幀優勢＝收尾那一招的「命中幀＋硬直－長度」。

套用： X→X 收尾是 ID 4，X→Y 收尾是 ID 3，兩招都播 AM_Attack_02、用 Damage 3。被防是 10＋28－40＝－2，打中是 10＋32－40＝＋2。

在 Frame Bar 上讀同一個數字

  • Frame Bar 在畫面上方，上下兩條分別是 1P 與 CPU，每格一個設計幀，兩條在時間上對齊。
  • 綠色是傷害判定前，紅色是判定中，黃色是收招；深紫色是 Hitstun，淺紫色是 Blockstun。
  • 綠色、紅色、黃色以外的灰格，代表這一方可以行動。
  • 先恢復的一方能動的那一幀，兩條的右側各自顯示自己視角的幀優勢：藍色 +N 代表比對手早恢復，紅色 -N 代表比對手晚恢復，白色 0 代表同時恢復。連段打到一半時雙方都不能動，所以不顯示。
  • 要讓 CPU 每一下都防，在 Console 輸入 tnda.Debug.CPUDefense on；改回 tnda.Debug.CPUDefense auto 就恢復 AI 自己抽防禦。

圖 3｜X→X→X 全被防住時的 Frame Bar（遊戲截圖）

這張圖就是上面 X→X→X 的情況 A：

  1. 1P 條：由左往右有三組「綠→紅→黃」，依序是 ID 1、ID 4、ID 5。
  2. CPU 條：開頭的灰格是還沒被打到、仍能行動；第一段打到後轉成淺紫的 Blockstun，三段連著防，一路延續到最右邊。
  3. 比較兩條的結尾：1P 最後一格黃色之後接了 3 格灰色，代表你已經能動、CPU 還在 Blockstun。這 3 格就是幀優勢。
  4. 讀右側數字：1P 那一行的藍色 +3 就是上面算出的 ＋3；CPU 那一行的紅色 -3 是同一件事從 CPU 看，晚 3 幀恢復。

實作練習要看的，就是 1P 那一行的數字。

要讀的程式

  • Source/TndaFighter/Fighting/FightingCharacter.cpp 的 AFightingCharacter::UpdateFrameAdvantage：每一幀檢查這次攻防是否已有一方恢復。
  • 同檔的 AFightingCharacter::ResolveFrameAdvantage：攻擊方先恢復時，取防守方剩下的硬直當正數；防守方先恢復時，取攻擊方剩下的動畫時間當負數。
  • 同檔的 AFightingCharacter::StartAttack：空檔起手才把 AttackSequenceSerial 加一，連段接招沿用原號。
  • Source/TndaFighter/Fighting/FightingCpuCharacter.cpp 的 AFightingCpuCharacter::UpdateAIDefenseDecision：看到新序列才抽防禦；抽到後，序列沒換就一直維持防禦。
  • Source/TndaFighter/Fighting/FightingFrameBar.cpp：把雙方每一幀的狀態記成一格顏色，讓上面的算式能直接在畫面上對照。

課前實作練習｜讓重招收尾，被防住也不吃虧

只修改 _DataTable/CommandTable.csv 的 Link、Opener（可以新增列，但 Montage 與 Damage 只能用既有的）與 _DataTable/DamageTable.csv 的 Hitstun、Blockstun，Reimport 到 DT_Command 與 DT_Damage。完成後，做出一套至少三段的連段，最後一段必須是第二攻擊（AM_Attack_02）或右腳踢頭（AM_Attack_03），而且 CPU 全部防住後，你不吃虧。

上課時分享畫面，進入 PIE 後依序：

  1. 按 Space 暫停。
  2. 按右 Ctrl＋F12 打開 Combat Debug。
  3. 按 ` 開 Console，輸入 tnda.Debug.CPUAI off，讓 CPU 不會行動。
  4. 再輸入 tnda.Debug.CPUDefense on，讓 CPU 每一下都防。
  5. 再按 Space 繼續，從空檔連按打完整套連段，讓大家看到 Frame Bar 右側的 1P 數字是 0 或正數。
