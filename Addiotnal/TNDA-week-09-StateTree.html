每個時間標籤（如 15:57）點下去都會從該秒數開始播放。

1. 一分鐘結論

  • StateTree = 行為樹的階層選擇 + 狀態機的轉移。從 Root 往下依 Enter Condition 選到葉節點；整條作用中分支上的 Task 會同時執行，直到某個 Transition 觸發。
  • 分工：Evaluator 收集資料（不做事）、Condition 把關、Task 做事、Transition 決定下一步。作者用「編輯部」比喻：Task 是記者、Transition 是編輯、Evaluator 是幕後研究員。
  • 資料怎麼流：Schema 定義 Context（Actor、AIController）；Evaluator／Task 的屬性用 Category Context／Input／Output 決定綁定方式；Parameters 是全樹共用變數。
  • 最容易踩的兩個坑：State 的 Task 完成條件預設是 Any（多半要改 All）；Enter Condition 不靈時，改把條件放在前一個 State 的 Transition上。
  • 一定要有保底狀態：作者把 Idle 放第一個子狀態，所有條件都不成立時樹才不會停掉。

4. 核心概念速查

State

一段自成單位的行為。被選中時，從 Root 到葉的整條分支同時作用中，各自帶著 Task 與 Transition。13:52

Custom Tick Rate

不必每幀更新。0.25 代表每秒更新 4 次，邏輯不需要即時時可省效能。14:20

Condition

Enter Condition 決定能不能進入；Transition Condition 決定何時離開。14:46

Task

真正做事的節點，可輸出資料給後面的 Task 使用（例如位置、目標）。15:09

Transition

依 Task 成功／失敗、事件或條件觸發；從葉往根檢查，第一個成立的勝出。15:33

Evaluator

持續更新的「狀況感知」：距離、血量、是否看到目標。條件判斷時答案已經準備好。9:18

Schema & Context

AI Component Schema 才拿得到 AIController；自訂 Schema 可把 Context 指定成自己的角色與 Controller 類別。5:13

Parameters

全樹共用變數。範例把 EQS 結果存成 Parameter，方便其他狀態取用。27:47

Global Task

整棵樹存活期間都在跑。作者建議非必要不用，因為它持續執行。6:50

屬性 Category 對照

Category行為典型用途
Context自動帶入 Schema 的 Context 值Actor、AIController
Input設計者必須在編輯器綁定來自 Evaluator 或 Parameter 的值
Output由節點寫入，供其他節點綁定距離、目標、隨機位置
其他名稱（如 Task、Parameter）可直接填值，也可以選擇綁定Montage、播放速率、技能 Tag 清單

5. 執行流程

啟動：隱式進入 Root→檢查 Enter Condition→成立就往子狀態走→直到葉狀態
整條分支的 Task 同時執行→每次 Tick 由葉往根檢查 Transition→第一個成立的 Transition 決定下一次選擇
狀態失敗→回到 Root 重新往下選→全部不成立時樹會停止（所以要有保底狀態）
事件驅動的寫法：Patrol、Combat 都設 Required Event to Enter。沒有事件時，樹會在 Root 與 Idle 之間來回；Controller 的感知 delegate 送出 Gameplay Tag 事件後，Idle 的 Transition 才把樹帶進對應分支。17:16

6. 範例樹拆解

依旁白重建的結構，節點名稱為示意，實際命名以範例專案為準。

Root ├─ Idle（保底；Tick 0.25；設走速 200） │ Transition：收到 Combat 事件 → Combat；收到 Patrol 事件 → Patrol ├─ Patrol（Required Event：Patrol） │ ├─ MoveToRandomLocation（Tick ≈ 0.3；Tasks = All） │ │ 設走速 200 → 取半徑內隨機點（Output）→ Move To 該點 │ │ 完成 → 下一個狀態 │ └─ LookAround：Delay 5 ±1.5 秒 → 回 MoveToRandomLocation └─ Combat（Required Event：Combat） ├─ DrawWeapon（Enter：Is Character Armed + Invert） │ Play Montage（拔武器）→ 下一個狀態 └─ AttackDefense（容器，每輪重新評估） ├─ IsPlayerDead → 讓樹 Succeeded ├─ Flee（Enter：Evaluator 血量 ≤ 20） │ Run EQS（遠離玩家）→ 結果存 Parameter → 跑速 400 → Move To ├─ Defense（Enter：玩家攻擊中）→ Block（GAS 格擋） ├─ TargetLost（目標無效）→ 清除 Focus → 送 Patrol 事件 ├─ SetFocus（目標有效） │ Transition：距離 > 250 → CloseDistance；否則 → Strafe ├─ CloseDistance：跑速 → Move To 目標 Actor（接受半徑 125） ├─ Strafe：甜甜圈 EQS → Move To → 短暫停頓 └─ PerformAttack：從技能 Tag 清單隨機／依序挑一招 → 回 AttackDefense

這棵樹示範了三種常用模式：保底狀態、事件驅動進入大分支、容器狀態裡的迴圈（每個子狀態完成後回到容器，重新評估優先順序）。

7. 陷阱與排錯

陷阱 1：Task 完成條件預設 Any
新建 State 時，Tasks 完成條件是 Any：任何一個 Task 完成就嘗試轉移，後面的 Task 可能還沒跑完。依序執行的 Task 多半要改成 All。加了 Debug Text 這類瞬間完成的 Task 時最容易出事。19:39
陷阱 2：Enter Condition 行為不如預期
作者的做法：把判斷移到前一個 State 的 Transition Condition 上，明確指定要去哪個狀態。32:31
陷阱 3：沒有保底狀態
所有狀態都選不進去時，樹會報錯停止，AI 原地不動。把一定進得去的 Idle 放在 Root 第一個子狀態。16:10
陷阱 4：C++ Task 的 Tick 不會跑
class 版 Task 要在建構子設 bShouldCallTick = true。42:11
陷阱 5：需要等待的 Task 太早結束
播放 Montage 這類動作，EnterState 要回傳 Running，Tick 確認完成才回 Succeeded。45:06

作者的設計建議

  • 樹外系統需要的資料（例如鎖定目標）放在 AIController，不要只存在 Evaluator。8:20
  • 每個自訂節點都寫 GetDescription，樹上就看得懂每個節點在做什麼，隔幾週回來或交接都省事。44:11
  • 只該執行一次的狀態（例如拔武器）不要放在 Tick 驅動的迴圈裡。22:55
  • Task 參數寫成可設定（例如技能清單、EQS 半徑），不同敵人就能共用同一個 Task。35:13

骨架：Condition

以下骨架是本筆記依影片說明整理的示意，不是範例專案原始碼。函式簽章請以所用引擎版本的標頭檔為準。示意

UCLASS(meta = (DisplayName = "Is Character Armed"))
class UIsCharacterArmedCondition : public UStateTreeConditionBlueprintBase
{
    GENERATED_BODY()

protected:
    virtual bool TestCondition(FStateTreeExecutionContext& Context) const override;

    // Context：由 Schema 自動帶入
    UPROPERTY(EditAnywhere, Category = "Context")
    TObjectPtr<AActor> Actor;

    UPROPERTY(EditAnywhere, Category = "Parameter")
    bool bInvert = false;
};

骨架：class 版 Task（需要等待事件）

UCLASS()
class UPlayMontageTask : public UStateTreeTaskBlueprintBase
{
    GENERATED_BODY()

public:
    UPlayMontageTask() { bShouldCallTick = true; } // 沒開就不會 Tick

protected:
    virtual EStateTreeRunStatus EnterState(FStateTreeExecutionContext& Context,
        const FStateTreeTransitionResult& Transition) override;   // 播放、綁定事件，回 Running
    virtual EStateTreeRunStatus Tick(FStateTreeExecutionContext& Context,
        const float DeltaTime) override;                          // 旗標成立才回 Succeeded
    virtual void ExitState(FStateTreeExecutionContext& Context,
        const FStateTreeTransitionResult& Transition) override;   // 解除綁定、停止 Montage

    UPROPERTY(EditAnywhere, Category = "Task")
    TObjectPtr<UAnimMontage> Montage;

    bool bMontageFinished = false;
};

USTRUCT()
struct FPerformAttackTaskInstanceData
{
    GENERATED_BODY()

    UPROPERTY(EditAnywhere, Category = "Context")
    TObjectPtr<AActor> Actor = nullptr;

    UPROPERTY(EditAnywhere, Category = "Parameter")
    TArray<FGameplayTag> AbilityTags;

USTRUCT(meta = (DisplayName = "Perform Attack"))
struct FPerformAttackTask : public FStateTreeTaskCommonBase
{
    GENERATED_BODY()

    using FInstanceDataType = FPerformAttackTaskInstanceData;
    // 編輯器靠這個函式找到要顯示的欄位
    virtual const UStruct* GetInstanceDataType() const override { return FInstanceDataType::StaticStruct(); }

    virtual EStateTreeRunStatus EnterState(FStateTreeExecutionContext& Context,
        const FStateTreeTransitionResult& Transition) const override;
    virtual EStateTreeRunStatus Tick(FStateTreeExecutionContext& Context,
        const float DeltaTime) const override;
};
