課前實作練習

課前實作練習 1｜做出 1P 從右側開場的場景

細步驟解答

  1. 在 Content Browser 開啟 /Game/Fighting/stage1。工具列 Play 的模式選擇 Selected Viewport，以便從遊戲畫面與編輯器交互核對。
  2. 在 World Outliner 選取 PlayerStart，於 Details 的 Player Start > Player Start Tag 確認值為 PlayerStart，記下 Transform > Location 的 X、Y、Z。再對 CpuStart 做同樣檢查，其 Player Start Tag 應為 CpuStart。這兩個物件都是 Player Start Actor，程式用這個欄位辨識用途。
  3. 在 Details 將兩個出生點的 Location 交換：PlayerStart 填入剛才記錄的 CPU 出生座標，CpuStart 填入原本玩家的出生座標。保留各自的 Player Start Tag，儲存關卡。沿用教材原始的左右站位時，交換後就是 1P 右、CPU 左。
  4. 按 Play，確認能操作的 1P 出現在 CPU 的螢幕右側。在遊戲畫面按 ~ 開啟 Console，輸入 tnda.Debug.ShowCombatDebug on、按 Enter，再收起 Console。
  5. 短按 A，讓 1P 向左靠近 CPU；按住期間應顯示 Forward 6，玩家上方小球為綠色。短按 D 則向右遠離，顯示 Backward 4、小球為紅色。鬆鍵後回到 Neutral。驗收時保留兩人間距，避免移動太久到達場地邊界。
  6. 核對學生記錄的出生座標與方向判定。解答應指出：Source/TndaFighter/Fighting/FightingPlayerCharacter.cpp 的 AFightingPlayerCharacter::DoMove() 仍將 A／D 換算成畫面左右的世界移動方向；共同父類在 Source/TndaFighter/Fighting/FightingCharacter.cpp 的 ClassifyRelativeDirection() 比較移動方向與對手方向。交換站位使對手方向反轉，因此同一個鍵的 4／6 也交換。SetCurrentRelativeDirection() 只在分類值改變時保存並廣播。
  7. 若站位沒有改變，回到關卡核對是否改到兩個出生點的 Location，以及兩個 Player Start Tag 是否仍各有一個。只改 World Outliner 顯示名稱不會交換出生用途。
  8. 成果核對後停止 PIE，將兩個出生點的 Location 還原成步驟 2 記錄的值，再儲存關卡。

課前實作練習 2｜讓 CPU 立即轉向，1P 保持平順轉身

細步驟解答

  1. 在 Content Browser 開啟 /Game/Fighting/Blueprints/BP_FightingCpuCharacter，點選工具列的 Class Defaults。在 Details 搜尋 Facing Interpolation Speed，記錄目前值；欄位分類是 Fighting Character > Facing。再開啟 /Game/Fighting/Blueprints/BP_FightingPlayerCharacter，記錄同一欄位的值。
  2. 對照 Source/TndaFighter/Fighting/FightingCharacter.h：FacingInterpolationSpeed 宣告在共同父類 AFightingCharacter，原生預設為 10.0f。Source/TndaFighter/Fighting/FightingPlayerCharacter.h 與 Source/TndaFighter/Fighting/FightingCpuCharacter.h 都宣告繼承這個父類，所以兩個角色可分別設定同一個欄位。
  3. 在 CPU 的 Class Defaults 將 Facing Interpolation Speed 設為 0；在 1P 的 Class Defaults 設為 10，各按 Enter 套用。分別 Compile 並 Save。這組答案以原生預設 10 作為 1P 平順轉身的比較值。
  4. 回到 /Game/Fighting/stage1 按 Play。CPU 應維持待機；若它自行移動，先檢查 CPU Class Defaults 的 CPU Test Movement > Test Movement Mode，本題使用教材的 關閉測試流程。
  5. 在遊戲 Console 輸入 tnda.Debug.FighterOverlap on。收起 Console，讓 1P 沿 A／D 方向穿過 CPU，移動到另一側再放開。雙方保持在一般地面狀態。
  6. 換邊時，CPU 應直接轉到新的對手方向，1P 則有平順轉身的過程。驗收看角色本身的轉向；首次開場兩者都會直接對正，不能只用開場畫面判斷參數是否有效。
  7. 對照 Source/TndaFighter/Fighting/FightingCharacter.cpp 的 UpdateFacing()：bShouldSnap 在首次面向或 FacingInterpolationSpeed <= 0.0f 時成立，直接使用目標旋轉；其他情況呼叫 FMath::RInterpTo()。因此 0 的效果是立即套用目標角度。雙方共用這段邏輯，各自讀取自己的速度值。
  8. 若在同一次 PIE 繼續使用正常碰撞，等兩個角色分開後輸入 tnda.Debug.FighterOverlap off；膠囊仍相交時，指令會拒絕恢復。成果核對後停止 PIE，將兩個 Blueprint 的面向速度還原成步驟 1 記錄的值，Compile 並 Save。停止 PIE 也會清除當次 Overlap 暫存設定。

課堂示範

課堂示範 1｜用向量內積判定前進 6 與後退 4

示範重點

  • 示範目標：讓學生用兩個方向的關係，解釋換邊前後 A／D 為何得到不同的 4／6。程式重點是 Source/TndaFighter/Fighting/FightingPlayerCharacter.cpp 的 DoMove()，以及 Source/TndaFighter/Fighting/FightingCharacter.cpp 的 ClassifyRelativeDirection()。
  • 兩個輸入向量：一個是玩家本次想走的世界方向，一個是由玩家指向 CPU 的方向。程式先移除 Z 並正規化，讓內積主要反映方向關係。兩個單位向量同向時內積為 1、反向為 -1、垂直為 0。
  • 分類門檻：FVector::DotProduct() 的結果嚴格大於 0.1 時為 Forward6，嚴格小於 -0.1 時為 Backward4，介於兩者之間、包含端點，皆為 Neutral。任一方向是零向量時也回傳中立。
  • 畫面對照：以綠色對手方向箭頭、玩家上方的方向小球與 Debug 文字，說明同一個 D 輸入在穿越 CPU 前後會由 6 變成 4。純 W／S 在正常格鬥構圖中與對手方向垂直，因此是中立；斜向輸入仍依內積判定。
  • 容易混淆的地方：判定使用輸入意圖，受阻時仍可能是 6；方向通知只在值改變時發出，持續按鍵與持續廣播是兩件事。DrawCombatDebug() 顯示目前值，不能把它當成通知次數或歷史輸入紀錄。

課堂示範 2｜把對手方向轉成平順的角色面向

示範重點

  • 示範目標：分清「由對手方向求目標角度」與「讓目前角度逐幀追上目標」。程式集中在 Source/TndaFighter/Fighting/FightingCharacter.cpp 的 RefreshOpponentDirection()、UpdateHorizontalOpponentDirection() 與 UpdateFacing()。
  • 朝向目標（Look At Rotation）：雙方位置先形成水平對手方向，再以 LastValidOpponentDirection.Rotation().Yaw 求出 DesiredFacingYaw。這就是本專案實作朝向目標旋轉的方式。
  • 旋轉插值（Rotation Interpolation）：FMath::RInterpTo() 讀取目前旋轉、目標旋轉、DeltaSeconds 與 FacingInterpolationSpeed，結果交給 SetActorRotation()。速度控制追向的快慢；角色實際面向可在一段過程中落後目標面向。
  • 參數與比較基準：原生預設 10 提供平順追向；改成較小的正值會轉得較慢；0 走立即套用的分支。首次有效面向直接對正，轉身差異應以開場後的換邊來比較。藍色 Debug 箭頭只表示目標角度，不能單憑箭頭判斷插值快慢。
  • 近距離保留方向：雙方水平距離不大於 10 公分時沿用最後有效方向，避免接近同一位置時方向反覆跳動。若從未取得有效方向，就保留目前旋轉。這個距離規則與追向速度分別控制不同的事情。
  • 本週的適用狀態：IsInNormalGroundState() 限定一般地面待機或移動；離地、播放 Montage 或使用 Root Motion 時暫停寫入 Actor Rotation。方向分類與自動面向共用對手方向，分類不需要等角色完成轉身。

課堂實作

課堂實作 1｜把換邊後的轉身速度調慢

題目

將 PIE 中 1P 執行個體的 Facing Interpolation Speed 改為 1，做出換邊後明顯較慢的轉身。比較原值與新值的表現，完成成果要能展示 1P 逐漸轉向另一側的 CPU。

在轉身尚未完成時，搭配 Debug 檢查同一個移動輸入的 4／6，說明方向判定是否也跟著延後，以及程式依據。

參考答案

  1. 以 /Game/Fighting/stage1 進入 PIE，在 Console 分別執行 tnda.Debug.ShowCombatDebug on 與 tnda.Debug.FighterOverlap on。讓 1P 穿過 CPU 一次，先看原值的轉身表現。
  2. 放開移動鍵，按 Shift+F1 釋放滑鼠。在 World Outliner 選取本次遊戲生成的 BP_FightingPlayerCharacter 執行個體，在 Details 搜尋 Facing Interpolation Speed，記下目前值。原生預設為 10，實際值以這個執行個體為準。
  3. 將這名 1P 的欄位改為 1，按 Enter 套用。回到遊戲畫面點一下，沿相反方向穿過 CPU，再比較角色轉身。這次修改直接作用於目前的 1P。
  4. 驗收應看到 1P 換邊後仍有明顯追向過程。CPU、目標方向箭頭與 1P 身體可以先後朝向不同方向；其中藍色箭頭代表 1P 的目標，身體才顯示實際轉到哪裡。
  5. 持續按住同一個移動鍵穿越 CPU，離開雙方中心距離不大於 10 公分的方向保留區間後，4／6 會依新的對手方向更新，無須等待 1P 轉完身。以 1P 從左向右穿越為例，同一個 D 輸入會由 Forward6 變成 Backward4；放開輸入後是 Neutral。
  6. 程式依據：Source/TndaFighter/Fighting/FightingPlayerCharacter.cpp 的 DoMove() 將 MovementIntent 與 TryGetOpponentDirection() 的結果交給分類；Source/TndaFighter/Fighting/FightingCharacter.cpp 的 ClassifyRelativeDirection() 沒有讀取角色目前旋轉或 FacingInterpolationSpeed。速度只在 UpdateFacing() 寫入旋轉時使用。
  7. 若轉身沒有變慢，先確認 Details 選到的是正在遊戲中的 1P Actor，且欄位確實為 1，並以開場後的地面換邊比較。成果核對後停止 PIE，執行個體的速度與兩個 Console 開關會隨這次遊戲結束而清除。

課堂實作 2｜讓 CPU 開場就主動靠近 1P

題目

修改 /Game/Fighting/Blueprints/BP_FightingCpuCharacter 的 Class Defaults，利用既有的 Test Movement Mode，做出每次 Play 都會緩慢朝 1P 靠近的 CPU。

完成成果是儲存了這項設定的 CPU Blueprint：開場時即使 1P 沒有輸入，CPU 也會主動靠近；1P 換到另一側後，CPU 會改向新的 1P 位置移動。結束再 Play 一次，應能重現相同行為。

參考答案

  1. 在 Content Browser 開啟 /Game/Fighting/Blueprints/BP_FightingCpuCharacter，點 Class Defaults，在 Details 搜尋 Test Movement Mode。欄位位於 CPU Test Movement，先記錄原值；原生預設為 關閉測試流程。
  2. 將下拉選單改成 往 1P 方向靠近（慢），對應 EFightingCpuTestMovementMode::ApproachPlayerSlow。按 Compile，確認沒有編譯錯誤後 Save。
  3. 開啟 /Game/Fighting/stage1 並 Play，先不輸入移動。CPU 應主動靠近 1P；這次使用的是剛才儲存的 Blueprint 預設值。
  4. 在遊戲 Console 輸入 tnda.Debug.FighterOverlap on，讓 1P 用 A／D 穿過 CPU 到另一側。CPU 應改變靠近方向，繼續朝 1P 的新位置移動。
  5. 停止 PIE，再 Play 一次。CPU 應再次從開場就主動靠近，這才表示成果保存在 Class Defaults，而不只改到上一次遊戲的執行個體。
  6. 程式依據：Source/TndaFighter/Fighting/FightingCpuCharacter.h 宣告 TestMovementMode；Source/TndaFighter/Fighting/FightingCpuCharacter.cpp 的 AFightingCpuCharacter::Tick() 呼叫 UpdateTestMovement()。這個函式每幀透過 TryGetOpponentDirection() 取得由 CPU 指向 1P 的方向，慢速模式以 0.25 的輸入比例呼叫 AddMovementInput()。方向跟著目前對手位置更新，所以 1P 換邊後 CPU 也會改向。
  7. 驗收看「會主動靠近、換邊後改向、再次 Play 仍有效」。既有模式提供持續的移動輸入，靠近後可能接觸並推動待機的 1P；題目不以自動保持距離或攻擊行為作為完成條件。若 CPU 不動，先核對 Class Defaults 的選項、Compile／Save 結果，以及執行的是 stage1。
  8. 驗收與成果紀錄完成後停止 PIE，將 CPU Blueprint 的 Test Movement Mode 還原為步驟 1 記錄的值，再 Compile 並 Save，供後續課程使用。
