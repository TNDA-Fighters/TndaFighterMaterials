  2. 起招時讀標記並快照。 FightingCharacter.cpp 的 StartAttack() 呼叫 FFightingAttackTiming::ReadMontage()。遇到 UFightingAirborneArcNotifyState 時，記下起跳與落地秒數，並把 HorizontalDistanceCm、ApexHeightCm 與兩條曲線複製進 SelectedTiming；交接成功後寫入 AttackTiming。
  3. 每一幀先推進離地段。 AFightingCharacter::Tick() 先呼叫 UpdateAirborneArc()，再呼叫 UpdateAttack()。
  4. 到起跳秒數就起跳。 UpdateAirborneArc() 以 GetAttackPosition() 取動畫位置；位置進入離地段時呼叫 BeginAirborneArc()：記下起跳點與角色前方、記下對手是否在前方、把對 Pawn 的碰撞改成 Ignore、切成 MOVE_Flying。
  5. 依進度放置位置。 進度 Alpha 由動畫位置換算，AirborneArcAt(Alpha) 用水平進度曲線乘上距離、高度曲線乘上頂點高度。先水平掃掠，撞到牆就停在牆前；再垂直掃掠到目標高度，最後 SetActorLocation()。
  6. 到落地秒數就落地。 腳下有可站立地面時呼叫 LandAirborneArc()：切回 MOVE_Walking，和對手重疊就推開，恢復 Pawn 碰撞。腳下沒有地面時改成 MOVE_Falling，自然落下站穩後才落地。

這張圖只回答「軌跡參數從哪來、何時套用」。參數在起招時抄下，位置每一幀由動畫進度決定，不靠動畫的根位移。

追蹤路徑三｜FrameScenario 指令只執行一次，怎麼做到每一幀都推進？

輸入 tnda.Debug.FrameScenario G2 後，Execute() 跑完就結束，誰讓劇本每一幀都檢查一次？ Execute() 把 HandleEndFrame() 登記到引擎的 OnEndFrame 名單；之後引擎每幀結束時呼叫它，進度記在物件的成員變數。

  1. 遊戲啟動時登記指令。 Source/TndaFighter/Fighting/FightingFrameScenario.cpp 檔尾的全域物件 FrameScenarioCommand 建構時登記 Console 指令，輸入時呼叫 Execute()；只在非 Shipping 版本註冊。
  2. 輸入指令時只跑一次 Execute()。 寫入 G2 的 Plan（bCrossOverLink = true），ResetProgress() 把 Phase 設為 WaitIdle，再用 FCoreDelegates::OnEndFrame.AddRaw() 把 HandleEndFrame 加進名單，留下 EndFrameHandle。
  3. 引擎每幀結束時通知名單。 引擎主迴圈每跑完一幀，就在 LaunchEngineLoop.cpp 呼叫 FCoreDelegates::OnEndFrame.Broadcast()，HandleEndFrame() 被呼叫一次。
  4. 依 Phase 推進一步。 WaitIdle 時，雙方可行動就 Place() 擺位，改成 Settle；Settle 時，站穩 0.3 秒就送 6Y，改成 Exchange。
  5. Exchange 依 Plan 交給 Handler。 bPlayerChains 交給 HandleBranchFrame()，bCrossOverLink 交給 HandleCrossOverFrame()。收幕那一幀設成 Done，之後每幀第一行看到 Done 就 return。
  6. 輸入 off 移除登記。 Stop() 呼叫 OnEndFrame.Remove(EndFrameHandle)，引擎不再呼叫。

這張圖只回答「每一幀由誰呼叫、進度存在哪裡」。Execute() 只負責登記，每一幀的工作由引擎呼叫 HandleEndFrame() 完成。

說明：Execute() 從頭到尾只跑一次，就是在 Console 輸入指令的那一刻。它本身不做「每一幀」的事，而是把 HandleEndFrame 登記到引擎的 FCoreDelegates::OnEndFrame。OnEndFrame 是引擎提供的一份「每幀結束時要通知的名單」（multicast delegate）；AddRaw(this, &HandleEndFrame) 把這個物件的 HandleEndFrame 加進名單，回傳的 EndFrameHandle 是登記憑證。引擎主迴圈每跑完一幀，就在 LaunchEngineLoop.cpp 呼叫 FCoreDelegates::OnEndFrame.Broadcast()，名單上的每個函式都會被呼叫一次。輸入 off 時，Stop() 用 EndFrameHandle 把自己從名單移除，引擎就不再呼叫。Unity 對照：類似 C# 的 someEvent += HandleEndFrame;，只是這個事件每一幀都會觸發，所以 HandleEndFrame 就像一個在執行期掛上、取下的 Update()。

HandleEndFrame() 每次被呼叫都從第一行開始跑，本身不記得上一次做到哪裡。進度存在物件的成員變數，所以跨幀仍在：

成員變數 誰寫入 用途
Plan Execute() 寫一次 決定交給哪個 Handler：bPlayerChains 交給 HandleBranchFrame()，bCrossOverLink 交給 HandleCrossOverFrame()
Phase 每推進一步就改寫 決定這一幀做哪一步：WaitIdle、Settle、Exchange、Done
bCrossOverSent 等旗標 Handler 送招時設成 true 讓同一個動作只做一次

「每一幀交給哪一個 Handler」是兩層判斷，每幀重新判斷一次。下面是 HandleEndFrame() 的結構示意，省略了逾時與站位檢查：

void HandleEndFrame()                       // 引擎每幀呼叫
{
    if (Phase == EPhase::Done) return;      // 第一層：看 Phase，演完了就不做
    if (Phase == EPhase::WaitIdle) { /* 擺位 */   Phase = EPhase::Settle;   return; }
    if (Phase == EPhase::Settle)   { /* 送起手 */ Phase = EPhase::Exchange; return; }
    // 走到這裡代表 Phase == Exchange
    if (Plan.bPlayerChains)  { HandleBranchFrame(…);    return; }  // 第二層：看 Plan
    if (Plan.bCrossOverLink) { HandleCrossOverFrame(…); return; }
    // 其餘走 A～C 的攻防交換流程
}

這種「每次從頭跑、靠成員變數記住進度」的寫法稱為狀態機：Phase 決定演到第幾幕，Plan 決定這一場演哪一齣。選在幀結束推進，是因為這時本幀的命中結算與硬直計時都已處理完，讀到的是本幀最終狀態；掛在 Actor 的 Tick 上，執行順序會受其他 Actor 影響，可能讀到結算一半的狀態。

資料：Console 指令 → Execute() 寫入 Plan、Phase 並登記 OnEndFrame → 引擎每幀 Broadcast() → HandleEndFrame() 依 Phase 推進、依 Plan 分派 Handler → Stop() 移除登記。

延伸｜想驗證別的 Frame Data，怎麼加一個情境？

FrameScenario 只負責擺位、等時機、送招，再讀正式系統留下的結果；命中、硬直、幀優勢都不由它指定。所以要驗證新的幀資料，就是再寫一幕「劇本」，讓遊戲自己演一次。完整規則見教材專案的 _Wiki/FrameScenario情境設計與擴充.md。

落到程式的順序：

  1. FFrameScenarioPlan、ResolvePlan()：加代號與計畫欄位，同步更新 Console 的 Usage 字串。
  2. Execute() 的入口檢查與 CanPlaceBranch()：特殊站距或移位，要在改 AI、幀率之前就確認放得下。
  3. HandleEndFrame() 的等待、擺位與起手：共用規則夠用就不重寫；站距不同時，像 G 一樣在 PlanDistance() 加分支。
  4. 在對應的 Handler 寫每一拍：條件是「實際狀態＋窗口＋只送一次的旗標」，送招一律走 SubmitCommand()，並依 Started／Buffered／Rejected 推進。
  5. 收幕：讀角色實際留下的 ID、接觸與狀態，再寫 Log 與結果畫面。
  6. 清理：新旗標加進 ResetProgress()，再確認 Stop()、HandleWorldCleanup() 會清乾淨。
  7. 文件與驗收：更新 Docs/Combat.md 的情境表，跑新情境、A～G2 回歸、off 復原與拒絕條件的 PIE 驗收。

常見錯誤：只在 ResolvePlan() 加一個 case；結果行直接填預期的 ID；直接改 CurrentAttack.Id、Buffer 欄位或 Hitstun。這樣情境只是把預設答案演出來，失去驗證的意義。

  • 可以追問：「越過後改按 A＋U，但落點被牆擋住，又被推回 CPU 左邊，會怎樣？」答：不會接招。預約已存，但落地時 HasCrossedOpponent() 變回 false，IsCommandPreorderOpen() 與 IsCommandLinkOpen() 都不開，預約無法被消耗；Combat Debug 的 Crossed 會變回 no。這一點依原始碼與 _Wiki/CombatDebug判讀指南.md 推得，本次沒有實測。

需求：出界扣血回場

我想讓玩家或 CPU 在格鬥場中出界時，不再直接判負結束對局，而是受到固定扣血並立刻傳送回擂台內安全位置繼續戰鬥；只有出界扣血導致生命值歸零時才進入擊倒結算。

規格

  • 觸發條件：角色不在離地軌跡期間、雙腳站穩在非擂台地面（含牆頂與外層高台），且雙方皆尚未進入擊倒或勝利終態。
  • 出界扣血量：每次出界固定扣除 20 HP（最低夾在 0）。
  • 生命值歸零結算：若出界扣血後生命值為 0，角色不回場，停在原地進入擊倒終態（成因記為出界擊倒），對手依既有規則進入勝利終態；若同幀雙方皆歸零，則雙方皆進入擊倒終態、無勝方。
  • 回場傳送條件：出界扣血後生命值仍大於 0 時，於當幀立刻傳送回擂台地面。
  • 回場目標位置：沿「擂台圓心 → 角色出界位置」方向，放回距離擂台圓心 700 cm 內的擂台頂面安全位置（若角色原本就更靠近圓心則維持該水平距離內縮，不貼牆）；若該位置與對手重疊，則往擂台中心或切線側邊推開至不重疊，並貼齊擂台地面。
  • 回場狀態清理：回場時強制中斷角色進行中的攻擊、清除指令預約與移動速度、重設為地面站立狀態並立即面向對手，回場後立刻恢復可行動（依當下輸入或 AI 狀態進入待機或防禦）。
  • 雙方同幀出界：若同幀雙方皆出界，各自獨立扣血與中斷動作，仍有大於 0 HP 的一方各自傳送回場並彼此面向。

    • static bool ResolveRingOutReturnTargets(const FVector2D& DesiredPos, const FVector2D& OpponentPos, const FVector2D& ArenaCenter, double SafeRadius, float ContactDistance, TArray<FVector2D>& OutCandidates);（預計新增，純規則 static 函式）：若 DesiredPos 與 OpponentPos 距離小於 ContactDistance（雙方膠囊半徑和），依序產生「朝圓心退讓至不重疊」、「切線左／右推開至不重疊」與「對側安全點」候選清單（全數夾在 SafeRadius 內）。
    • bool TryFindArenaFloorAnchor(FVector2D& OutCenter, double& OutRadius, double& OutTopZ) const;（預計新增）：從 World 尋找唯一帶 ArenaFloor Tag 的 Actor，取 GetActorBounds(false, Origin, Extent) 計算圓心 (Origin.X, Origin.Y)、半徑 FMath::Min(Extent.X, Extent.Y) 與頂面高度 Origin.Z + Extent.Z。
    • void ProcessRingOutForCharacter(bool& OutShouldReturn, FVector& OutReturnLocation); 或分為兩段：
      1. bool EvaluateAndApplyRingOutDamage();（預計新增，取代原 QueueRingOutIfOutsideArena 的直接擊倒）：檢查 ShouldRingOut，成立時呼叫 Health->ApplyDamage(RingOutDamage)；若 Health->GetCurrentHealth() <= 0 則呼叫 QueueKnockedOut(EFightingKnockOutCause::RingOut) 回傳 false，否則回傳 true（標記本幀須執行回場）。
      2. void ExecuteRingOutReturn();（預計新增）：清理狀態、計算安全座標與防重疊 Sweep、更新位置與地面狀態、立即強制面向對手。
    • 既有 ShouldRingOut(bool bStandingOnGround, bool bOnArenaFloor, ECombatState Self, ECombatState Opponent) 維持簽名與語意不變（純規則仍為「是否觸發出界事件」）。

2. Init

  • 角色 BeginPlay() 與 AFightingGameMode::FinishRestartPlayer() 無需新增額外初始化；ArenaFloor 存在性仍由 AFightingGameMode 在開場驗證。
  • 若異常關卡在無 ArenaFloor（或超過一個 ArenaFloor）下進入呼叫 TryFindArenaFloorAnchor，函式回傳 false 並記 Warning，改退回以對手位置或原點作為參考中心、或安全放棄傳送而不崩潰。

3. Tick

  • 入口：AFightingCharacter::HandleWorldPostActorTick()（Source/TndaFighter/Fighting/FightingCharacter.cpp 約 1565 行）。
  • 流程與先後順序：
    1. 維持先結算雙方攻擊命中候選（TryApplyHit）。
    2. 接著對雙方分別呼叫 EvaluateAndApplyRingOutDamage()，記錄 bSelfRingOutReturn 與 bOtherRingOutReturn（先共同評估與扣血，避免先傳送者改變後者的空間或狀態）。
    3. 對待套用硬直／擊倒執行 ApplyPendingStun()（若出界已將某方 HP 扣至 0，這裡會套用 KnockedOut(RingOut)）。
    4. 對需要回場且尚未進入終態的角色（bSelfRingOutReturn && !IsCombatStateEnded(CombatState)）呼叫 ExecuteRingOutReturn()；同理處理 Target。
    5. 最後執行 ResolveMatchOutcome() 與結束攻擊收尾。
  • 算例：
    • 角色於 stage1（圓心 (1790, 1800)，半徑 900，頂面 Z=210）越頂落在 (2750, 1800, 210)（距圓心 960 cm，場外高台）：
      • SafeRadius = min(700, 900 - 200) = 700 cm。
      • 方向 (1, 0)，安全目標點 Desired2D = (1790 + 700, 1800) = (2490, 1800)。
      • 加上膠囊半高 CapsuleHalfHeight（約 88 cm）作垂直起點與向下 Sweep 找地面，Z 貼齊 ArenaFloor 頂面（約 210 + CapsuleHalfHeight）。
      • 若對手剛好站在 (2460, 1800)，水平距 30 cm < ContactDistance（約 68 cm），ResolveRingOutReturnTargets 會優先產生「朝圓心退開」位置 (2460 - 68, 1800) = (2392, 1800) 並以 Capsule Sweep 確認無牆體阻擋後放置。

4. End

  • ExecuteRingOutReturn() 的狀態清理（相當於回場重置）：
    • 若 UWorld* World = GetWorld() 有效，清除 StunTimer 與清空 PendingStunState = ECombatState::Neutral、PendingStunFrames = 0（取消同幀剛被命中但未歸零的硬直）。
    • 若正在攻擊或播反應：停止攻擊 Montage（StopAttackMontage／ReleaseAttackPlayback(true)）與反應 Montage（StopReactionMontage），清空 CommandBuffer（ClearCommandBuffer(TEXT("RingOutReturn"))），關閉 ActiveHitbox 與清空 HitCharacters。
    • 呼叫 HaltActiveMotion() 清零速度與加速度；若 AirbornePhase != None 或 MovementMode 不是 Walking，重設為 MOVE_Walking 並還原 Capsule 對 Pawn 的碰撞回應（確保不殘留 Flying 或穿透狀態）。
    • 透過 SetCombatState(ResolveIdleState(ECombatState::Neutral, EvaluateDefenseIntentAs(ECombatState::Neutral)), TEXT("RingOutReturn")) 立刻回到可行動狀態（Neutral 或 Defending）。
    • 重新更新朝向對手的方向向量並直接將 ActorRotation 設為面向對手（Yaw 朝向 Other），同步更新 DesiredFacingYaw 與 LastValidOpponentDirection。
    • 記錄 LogTndaFighter Log：Ring out return: actor=%s damage=%d hp=%d/%d from=%s to=%s floor=%s。
