課前實作練習

課前實作練習 1｜讓缺少 Montage 的角色拒絕攻擊，仍可正常移動

細步驟解答

本教案採 TndaFighter week-05（44e6c65）、UE 5.8。下列步驟是依 tag 原始碼、既有 MCP 驗收資料與 UE 文件整理的帶課操作，尚未在本次 session 完成 Editor／PIE 排練；欄位以英文名稱定位，若編輯器翻譯不同，以資產路徑及 C++ 欄位名核對。

  1. 先確認 Xbox 搖桿。Windows 辨識裝置後，開啟 /Game/Fighting/stage1，按 Play 並點一下遊戲畫面取得焦點。在場地中央依序測十字方向鍵、放開停止、X 單按與長按、放開再按。若鍵盤正常而搖桿無反應，先檢查 Windows 裝置連線及遊戲視窗焦點，不先改 IMC。需要釋放滑鼠時按 Shift+F1，結束測試按 Esc。
  2. 停止 PIE，按 Ctrl+Space 開啟 Content Drawer，進入 Content/Fighting/Blueprints，雙擊 BP_FightingPlayerCharacter。若看到精簡資料畫面，開啟完整 Blueprint Editor，再點上方 Class Defaults。
  3. 在 Details 搜尋 Basic Attack Montage（C++ 名稱 BasicAttackMontage）。原教材參照應為 AM_Attack_01。這是類別預設值，不是場景中玩家實例的屬性；不要使用「重設為原生預設」代替指定原教材參照。
  4. 用資產選擇欄的清除功能將值設為 None，按 Compile，再按 Save／Ctrl+S。只保存這個 BP；CPU BP 的參照保持原樣。
  5. 回到 stage1 開新 PIE，打開 Window → Developer Tools → Output Log，清除搜尋條件或搜尋 Attack rejected，確認 Warning 類別可見。讓玩家站在地面，保留有效 CPU 對手，按一次搖桿 X。
  6. 驗收時同時看三件事：玩家沒有出拳、Log 包含 command=X montage=None 及 reason=invalid animation configuration、十字方向鍵仍能移動。可再用 U 交叉確認；不要求截圖或另外提交紀錄。
  7. 口頭解答：AFightingCharacter::TryExecuteCommand() 在動畫設定檢查處返回，尚未執行成功播放後的 bIsAttacking = true。玩家 BP 清空參照，不代表 C++ 壞掉，也不會改到 CPU BP。
  8. 若沒有 Warning，先確認控制焦點、BP 是否編譯儲存、是否仍在攻擊／離地／無對手等更早就被拒絕的條件。這些早期拒絕不一定產生同一筆 Warning，不要直接把沒有 Log 判為課題成功。
  9. 停止 PIE，將玩家 BP 的 Basic Attack Montage 明確指定回 /Game/Fighting/Anims/AM_Attack_01，Compile、Save。重新 Play 確認 X 可播放一次，結束後仍可移動；此狀態才是練習 2 的起點。

課前實作練習 2｜做出慢速攻擊，讓操作鎖定跟著播放結束

細步驟解答

  1. 確認已停止 PIE，玩家 BP 已指定 AM_Attack_01。開啟 Content/Fighting/Anims/AM_Attack_01，先確認原始條件：片段範圍 0～1 秒、Play Rate 1、Loop Count 1、Default Section 的 Next 為 None、Slot 為 DefaultGroup.DefaultSlot，Auto Blend Out 開啟。
  2. 先以原始倍率在場地中央出拳一次，再停止 PIE。這是獨立比較的起點；不要沿用練習 1 的 None，也不要同時改 Blend 設定。
  3. 在 Montage 時間軸點選 MM_Attack_01 的動畫片段，到 Details 找 Play Rate，從 1 改成 0.5，按 Ctrl+S。不要改預覽播放器的暫時速度、Montage 全域倍率或原始 Sequence。
  4. 開新 PIE。先按 X 出招，再持續按住一個可移動方向。播放與完整淡出尚未結束時，角色預期不能主動移動；完整收尾後，持續按住的方向恢復移動。放開方向與 X，再按一次 X，應能再次出拳。
  5. 另做一次重按測試：攻擊中放開並重按 X，隨後放開，確認原攻擊不重啟，結束後也不自動補播。再一次新的按下才是下一次出招機會。
  6. 需要查看狀態時，PIE 中按 Shift+F1，在 World Outliner 選玩家執行個體；Details 搜尋 Is Attacking 與 Current Command。攻擊中預期為 true／X，收尾後為 false／None。欄位唯讀，不以修改它們完成題目；若面板無法即時看清，先依持續方向輸入、再次出招的結果驗收。
  7. 口頭解答：改動的是共用 Montage 裡的片段倍率，原 Sequence 資料及 C++ 播放入口保持原樣。OnMontageEnded 經 HandleAttackEnded() 呼叫 FinishAttack()，才清除狀態；程式沒有固定等一秒的解鎖 Timer。CPU 也引用同一個 Montage，但沒有自主攻擊 AI，因此不會因調倍率而自己出招。
  8. 若看不出變慢，檢查是否只改了預覽速度、是否已儲存正確資產、玩家是否仍引用原 Montage；若無法恢復移動，先核對 Loop Count、Section 連接與 Auto Blend Out。不要用手改 bIsAttacking 掩蓋設定問題。
  9. 停止 PIE，把片段 Play Rate 還原 1 並儲存，確認未改動 Blend In 0.10、Blend Out 0.15、Trigger Time -1。重開 PIE 確認恢復教材原始行為。

課堂示範

課堂示範 1｜Animation Montage 的核心機制與編輯

示範重點

  • 用 MM_Attack_01、AM_Attack_01 與 ABP_Manny_Combat 說明三個責任：Sequence 提供動作、Montage 安排片段與播放、Slot 讓動作進入 AnimGraph。BasicAttackMontage 是角色 BP 保存的參照，Montage_Play() 才是程式啟動播放的位置。
  • 以現有 Montage 認識時間軸、片段 Details、Asset Details、Section 與 Slot。示範 End Time 1 → 0.8 後還原，再獨立示範片段 Play Rate 1 → 0.5 後還原；片段使用範圍與速度會改變，原始動畫資料沒有被重寫。
  • 分開比較 Blend In 0.10 → 0.30 與 Blend Out 0.15 → 0.30，每次只改一項、儲存、進 PIE，再停止並還原。混合調整的是姿勢權重過渡，不等同於動作半速；維持 Auto Blend Out 與 Trigger Time -1，不把延長 Blend Out 說成整招必定等量延長。
  • 核對 Default → None 的單次 Section 接續與 DefaultGroup.DefaultSlot。AnimGraph 主路徑是 Main States → DefaultGroup.DefaultSlot → Control Rig → Output Pose。Slot 名稱必須對得上，本週不新增 Slot 或改 Skeleton。
  • 遊戲畫面依序使用 Tekken 101：00:26 的準備、生效、恢復，以及 TEKKEN 8 BEST SLOWMOS：00:20。戰鬥的 Active 需要命中判定，與「拳頭伸出去」不等同；本週只有播放，沒有 Hitbox。慢動作只能作視覺對照，不能宣稱《TEKKEN 8》一定使用 Montage Play Rate；世界時間倍率是另一種控制層。
  • 詳細點選、還原、逐頁話術與影片備案見同週教師講稿。最後銜接課堂實作 1：只拉長 Blend In。

課堂示範 2｜用 Montage 結束通知管理攻擊鎖定與恢復

示範重點

  • 核心順序是「資格與設定有效 → 播放成功 → 設定攻擊狀態 → 播放與淡出 → 完整結束通知 → 清理」。沒有成功播放就不能留下鎖定，開始淡出也不能提早解鎖。
  • DoMove() 先保存目前 4／6 語意，再阻擋攻擊中的 AddMovementInput()；IsInNormalGroundState() 則限制自動面向與自訂推擠。重力、碰撞及攝影機最大距離修正仍有效，不能把此處說成整個角色停止更新。
  • Instance->OnMontageEnded 綁定 HandleAttackEnded()；接到屬於當次播放的通知，才執行 FinishAttack(false)。播放身分只點出「避免舊通知解開新攻擊」，不展開弱參照與實例管理細節。
  • CancelAttack() 的 Stop() 開始淡出，仍須等完整結束。tag 沒有永久取消 Console 指令，課堂以程式帶讀中斷分支，不要求學生建立按鍵、呼叫測試 fixture 或改內部狀態。
  • Started 讓本教材每次按下只嘗試一次；鎖定中重按會被共用入口拒絕，不會排隊。HandleAttackEnded() 的 Attack ended 日誌原為 Verbose，銜接課堂實作 2 時只調整這筆等級。
  • 最後用 Tekken 101：00:26 與 00:54 說明 Frame Data 與雙方恢復時間差。+5F 表示攻擊方早 5 幀恢復，可用來維持壓制；下一招仍需考慮起手速度、距離與對手應對。+5F 是使用者提供的教學例，未逐格確認片中的特定招式；本週沒有防禦硬直或 Frame Advantage 計算。

課堂實作

課堂實作 1｜把攻擊起手的姿勢混合拉長

題目

以原始片段播放倍率 1 為基準，把 /Game/Fighting/Anims/AM_Attack_01 的 Blend In 從 0.10 秒改成 0.30 秒並儲存。只調整這一項，保留片段、Slot、Section、Blend Out 與 Auto Blend Out。

分享桌面展示新數值與起手姿勢的過渡，在 PIE 按搖桿 X 或鍵盤 U，確認仍只播放一次、結束後能恢復移動。口頭說明：拉長姿勢混合與降低片段 Play Rate，改變的是同一件事嗎？

參考答案

  1. 停止 PIE，確認片段 Play Rate 已還原 1，玩家 BP 的 Montage 參照有效。
  2. 開啟 AM_Attack_01，在 Asset Details → Blend In 展開混合設定，把 Blend Time 從 0.10 改成 0.30，Ctrl+S。不要改片段 Details 的 Play Rate；若面板未顯示，從 Window 開啟 Asset Details。
  3. 進 stage1 的 PIE，從待機出拳，比較進入攻擊姿勢的過渡。保持玩家遠離牆與 CPU，完整結束後再試移動及下一次攻擊。需要回看原值時，停止 PIE、還原 0.10 並儲存後獨立比較，不在同次播放中改值。
  4. 答案：Blend In 改變姿勢混合的過渡時間，Play Rate 改變片段播放速度；前者不等於把原始攻擊動畫拉成三倍長。混合差異以實際畫面判讀，不預先承諾固定的視覺幅度。
  5. 如果看到整招變慢，檢查前題 Play Rate 是否尚未還原；若只有預覽變化而 PIE 無差異，檢查資產儲存與角色引用。驗收同時看設定、畫面和操作恢復。
  6. 停止 PIE，將 Blend In 還原 0.10、儲存，確認 Blend Out 仍為 0.15。這項改動發生在雙方共用的 Montage，不是玩家 BP 的個別覆寫。

課堂實作 2｜讓每次正常攻擊結束留下可見的 Log

題目

在 Source/TndaFighter/Fighting/FightingCharacter.cpp 的 HandleAttackEnded() 中，只把既有 Attack ended 那一筆 UE_LOG 的等級從 Verbose 改成 Log，保留文字、參數與收尾邏輯。完成建置後，做出每次正常收尾都能在 Output Log 看到紀錄的版本。

分享桌面展示該行修改、正常攻擊結束後的一筆 Log，以及恢復移動和再次出招。Log 應包含角色、command=X、Montage、instance 與 interrupted=0；攻擊中重按不會為被拒絕的輸入多生一筆結束紀錄。口頭說明：這筆 Log 對應的是按下攻擊鍵，還是某次播放完整結束？

參考答案

  1. 先把前題的資產設定還原並儲存，停止 PIE、關閉 Unreal Editor。在 IDE 開啟教材專案的 FightingCharacter.cpp，找到 HandleAttackEnded()。tag 的位置約在第 460 行，以函式及 Attack ended 文字定位，不依賴修改後行號。
  2. 將該筆 UE_LOG(LogTndaFighter, Verbose, ...) 改為 UE_LOG(LogTndaFighter, Log, ...)。只改 Verbose 這個引數；Attack started、Attack cancel 與 FinishAttack(false) 保持原樣。
  3. 儲存 C++，在已配置的 IDE 選 Development Editor／Win64，建置 TndaFighter。本題採關閉 Editor 後的完整建置，不混用 Live Coding。確認建置成功再重新開啟 TndaFighter.uproject；建置失敗先處理錯誤，不以舊 DLL 驗收。
  4. 開啟 Output Log。在底部 Console 輸入 log LogTndaFighter Log，確保不是先前開啟的 Verbose 讓原紀錄本來就可見。清除不相關搜尋條件，再以 Attack ended 篩選。
  5. 開新 PIE，按一次 X，等完整正常結束。驗收一筆包含 command=X、AM_Attack_01、instance=、interrupted=0 的紀錄；記錄出現前後都用實際移動及再次出招確認行為。
  6. 另一次攻擊中放開、重按 X 後再放開。預期原攻擊只收尾一次，鎖定中的輸入沒有新增播放，因此不應多出第二筆結束紀錄。驗收不要把停止 PIE 的清理或其他角色播放混進計數。
  7. 答案：日誌位於 HandleAttackEnded() 的身分檢查之後、FinishAttack(false) 之前，記錄的是當次播放收尾，不是每一次按鍵。interrupted=0 表示正常結束；此題不要求製造中斷。
  8. 若沒有 Log，先確認重建成功且 Editor 載入新版本、搜尋條件與日誌等級正確、攻擊確實完整播放。若根本沒有攻擊，回頭檢查 Montage 參照，不能在收尾函式加更多狀態修改繞過原因。
  9. 展示完成後關閉 Editor，將同一引數還原 Verbose，重新完整建置後再開啟專案。助教在自己的排練紀錄保存版本、建置方式與結果；學生不另交證明檔。
