課前實作練習

課前實作練習 1｜讓第二攻擊只命中頭部，並調整命中傷害

細步驟解答

  1. 停止 PIE，確認交付基準：_DataTable/CommandTable.csv 的 ID 3 是 Y、Hitbox=hand_l、Damage=3、Hurtboxes="head,pelvis,calf_l,calf_r"；_DataTable/DamageTable.csv 的 ID 3 Damage=20。在 Content Browser 開 /Game/DataTable/DT_Command 與 /Game/DataTable/DT_Damage，核對列 3；CSV 與表值不一致時，對對應 DataTable 右鍵選 Reimport，修正 Row／Field 錯誤後才繼續。
  2. 開 /Game/Fighting/stage1、按 Play，點入遊戲視窗，按反引號鍵（~ 所在鍵）開啟 Console，輸入 tnda.Debug.ShowCombatDebug on 與 tnda.Debug.CpuAlwaysDef off。每條指令按 Enter 執行，再關閉 Console。靠近 CPU，放開方向鍵，按 I 出 Y；找出能看到身體部位命中標記的距離。命中部位會短暫標紅並標名，CPU 在 HP 足夠時減 20；需要輔助時在 Window → Developer Tools → Output Log 查看 Hit 的 hurtbox、damage 與 deducted。
  3. 停止 PIE，只把 Command CSV 的 ID 3 Hurtboxes 改為 "head"，保留其餘欄位與 CSV 引號，儲存；對 DT_Command 右鍵 Reimport，開表確認列 3。重開 PIE、開啟 Combat Debug 並關閉 CPU 強制防禦。
  4. 以相同招式比較：原先的身體接觸不能再結算；調整位置與距離，讓左手軌跡接觸頭部，確認出現 head 標記且 HP 減 20。清單外的接觸不消耗本次揮擊的命中機會，稍後碰到頭部仍可結算一次。若整次揮擊沒有碰到頭部，就不扣血；不能把這種結果說成資料自動把拳頭移到頭上。教師備課須先找出可重現的比較位置，不以動畫看似碰到作為命中證據。
  5. 停止 PIE，只把 Damage CSV 的 ID 3 Damage 從 20 改成 33，儲存；對 DT_Damage 右鍵 Reimport，開表確認列 3。重開 PIE，以同一個可命中頭部的位置按 I；第一次成功命中預期 CPU 從 100 變成 67，標記仍為 head。比較前一階段的 20 點與本階段的 33 點；每次確認剩餘 HP 足夠，避免夾值讓實際扣除量小於表值。
  6. 請學生指著兩張資料表與畫面，用自己的話說明：Hurtboxes 限定對手哪些部位接觸可結算，Damage 表決定扣血數字；Command 的 Damage=3 是索引。只允許 head 不保證每次命中，Hitbox、動畫與 Notify 時間也沒有改。驗收採現場操作與口頭說明，不要求另交 Log 或截圖。
  7. 在 PIE Console 輸入 tnda.Debug.CpuAlwaysDef off、tnda.Debug.ShowCombatDebug off，再停止 PIE。將 Command ID 3 Hurtboxes 還原為 "head,pelvis,calf_l,calf_r"、Damage ID 3 傷害還原為 20，儲存並分別 Reimport 兩張 DataTable，核對列 3；其他欄位與資產保持原值。

課前實作練習 2｜用除錯指令看懂命中與防禦

細步驟解答

  1. 確認練習 1 已還原，DT_Damage 的 ID 1 傷害是 10、雙方 MaxHealth 為 100。開 stage1 新 PIE、點入遊戲視窗，以反引號鍵開 Console，輸入 tnda.Debug.ShowCombatDebug on 與 tnda.Debug.CpuAlwaysDef off，關閉 Console。畫面應顯示 Hurtbox 與雙方 HP。
  2. 移到 X 可命中的距離，放開方向鍵，只按 U 出 X。觀察短暫 Active Hitbox、命中部位標記、CPU 受擊反應與 HP 減 10；需要輔助時查看 Output Log 的 Hit 紀錄。不要以「動畫播放了」判定已命中。
  3. 保持角色位置，等招式與反應結束後，在 Console 執行 tnda.Debug.CpuAlwaysDef on。再按 U 出 X，確認有效接觸後 CPU 播放防禦反應，HP 不再減少；Log 對應 Guard。若根本沒有命中，先確認距離與 Active 判定，不能只以 HP 不變宣稱防禦成功。
  4. 再執行 tnda.Debug.CpuAlwaysDef off，等待反應結束後按 U，確認後續命中恢復受擊與扣血。若只有上述三次有效命中，CPU HP 預期為 100→90→90→80。開關不會追溯補扣或回復先前的血量。
  5. 請學生自己切換兩個開關，再以畫面說明各自的作用。可先關閉 ShowCombatDebug 出招，觀察除錯疊圖消失但攻擊仍可結算，再開啟以讀取 HP；CPU 強制防禦則改變有效命中後的結果。請學生用 Active／接觸、反應與 HP 解釋一般命中、防禦和未命中，避免把除錯顯示當成命中判定開關。
  6. 在 PIE Console 關閉 tnda.Debug.CpuAlwaysDef 與 tnda.Debug.ShowCombatDebug，再停止 PIE。核對 CSV、DataTable、Blueprint 與 Notify 沒有因本題被修改；新 PIE 的 HP 回到 MaxHealth，除錯顯示則重新採用 Blueprint 的既有預設。

課堂示範

課堂示範 1｜兩張 DataTable 如何把招式、部位與傷害串起來？

示範重點

以三列 Command 和 Damage 表建立跨表關係：ID 是 Row Name，Command.Damage 是索引，Damage.Damage 纔是扣血值。把整理後的招式副本與結算當下查表分開；用一次 Reimport 和錯誤引用說明資料驗證。Health 上限、招式資料與執行期剩餘血量各有不同責任。

課堂示範 2｜Active 時間、連續軌跡與一次揮擊一次傷害

示範重點

以 Damage Notify State 建立 Active 時間概念，再區分除錯元件開關與正式軌跡候選。候選經對手、部位、去重與傷害查表才結算；同一揮擊一次結算是命中集合的規則。只帶讀短路徑，不展開連續幾何數學、長幀補查、防禦反應或 KO。

課堂實作

課堂實作 1｜把 1P 的最大生命值提高到 150

題目

只改玩家 Blueprint 既有 Health 元件的 MaxHealth，做出每次新 PIE 中 1P 為 150/150、CPU 仍為 100/100 的版本。遠端展示設定與雙方 HP，說明重新開局為什麼採用新的滿血值；保留其他資料，驗收後還原。

參考答案

  1. 停止 PIE，開 /Game/Fighting/Blueprints/BP_FightingPlayerCharacter，在 Components 選 Health，Details 搜尋 Max Health，由 100 改 150，Compile、Save。
  2. 開 stage1 新 PIE，開 Combat Debug，查看雙方 HP；玩家預期 150/150，CPU 100/100。
  3. 讓玩家有剩餘 HP 變化時再停止／重開 PIE，從 FightingHealthComponent.cpp::BeginPlay() 解釋 Reset；沒有受傷條件時直接以新局滿血與程式核對，不新增 CPU 功能。
  4. 停止 PIE，還原玩家 MaxHealth=100，Compile、Save，再開新局確認；CPU 與 Damage 表保持原值，關閉 Debug。

課堂實作 2｜把玩家右手的命中球縮小

題目

只把玩家既有 Hitbox_hand_r 的 Sphere Radius 從 20 改為 10 cm。遠端展示元件值與 X 招 Active 時較小的球，確認 CPU 對應設定仍為 20；說明改變的是空間還是時間。保留骨骼附掛、動畫與資料表，驗收後還原。

參考答案

  1. 停止 PIE，開玩家 BP，在 Components 選 Hitbox_hand_r，Details 的 Shape／Sphere Radius 由 20 改 10，Compile、Save；不要改 Transform 或 Attach Socket。
  2. 開 CPU BP 核對同名元件仍為 20，不儲存任何改動。
  3. 開 stage1 PIE、開 Combat Debug，按 U 看 Active 球。以半徑設定與球的縮小驗收，不要求量測或證明特定邊界命中。
  4. 指向 PrepareContinuousHitDetection() 的球半徑快照：新招式讀取形狀；Damage Notify 的時間沒有改。
  5. 停止 PIE，玩家半徑還原 20，Compile、Save，關閉 Debug。
