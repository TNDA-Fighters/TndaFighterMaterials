Week 08 助教參考：命中推拉與鏡頭震動

本文件提供「命中推拉與鏡頭震動」的手動實作、建置匯入與測試步驟。程式片段尚未放入專案編譯或執行 PIE 驗證，請依步驟逐段確認。

手動實作教學：Init → Tick → End

這一節開始是教師可依序操作的全手動流程，不需要請 AI 改碼或透過 MCP 匯入。使用 IDE／文字編輯器修改 C++ 與 CSV，再手動建置、在 Editor 匯入並測試。

Init 表示開始一次效果，Tick 表示逐幀更新，End 表示停止並清除狀態。下列步驟按已查讀的 week-08 原始碼安排，請依函式名與附近程式定位，不依固定行號。程式片段尚未放入專案編譯與 PIE 驗證，明天試作時請逐階段確認。

閱讀程式片段時，請先確認操作類型：新增成員貼在 header 的類別大括號內；新增函式定義貼在 cpp 的檔案層級，不要貼進其他函式；插入呼叫才貼進指定的既有函式。每段只加一次。每套效果各自完成步驟 1～5 後就建置與測試，通過後再做下一套，避免只有宣告卻還沒寫完定義時出現連結錯誤。

開始前：確認專案與工具

  1. 在老師提供的 week-08 示範專案目錄執行 git status --short，保存已有改動。不要為了對齊教材直接還原工作樹。
  2. 準備可編輯 C++ 的 IDE、文字編輯器與 Unreal Editor。以下 C++ 路徑皆以 Source/TndaFighter/ 為起點，CSV 位於專案根目錄 _DataTable/。
  3. 先開啟 stage1，Play 確認原有 U → I 能出招，再 Stop。保存目前需要的資產，正常關閉 Editor，避免修改 USTRUCT／enum 時只靠 Live Coding 更新。
  4. 執行順序為：資料欄位 → 建置與匯入 → 推拉 → 建置與測試 → Shake → 建置與測試。每完成一段保存一次 Git 進度，失敗時先修好再繼續。

完成後怎麼確認

2. 在 Reader 加入完整數字檢查

開啟 DataTable/TndaDamageReader.cpp，在 include 區塊之後、UTndaDamageReader::Prepare() 之前加入以下函式。放在 WITH_EDITOR 內，因為它檢查的是 Editor 的來源 CSV 原文：

#if WITH_EDITOR
namespace
{
    bool ParseHitPushX(const FString& Text, float& OutValue)
    {
        OutValue = 0.0f;
        if (Text.IsEmpty()) { return false; }

        // 只接受正負號、數字及一個小數點，避免把 "30cm" 當成 30。
        int32 Index = (Text[0] == TCHAR('+') || Text[0] == TCHAR('-')) ? 1 : 0;
        bool bHasDigit = false;
        bool bHasDot = false;
        for (; Index < Text.Len(); ++Index)
        {
            const TCHAR C = Text[Index];
            if (C >= TCHAR('0') && C <= TCHAR('9'))
            {
                bHasDigit = true;
            }
            else if (C == TCHAR('.') && !bHasDot)
            {
                bHasDot = true;
            }
            else
            {
                return false;
            }
        }
        if (!bHasDigit) { return false; }

        // 先以 double 轉換，再限制為 float 可保存的有限範圍。
        const double Value = FCString::Atod(*Text);
        if (!FMath::IsFinite(Value) ||
            Value > MAX_flt || Value < -MAX_flt)
        {
            return false;
        }
        OutValue = static_cast<float>(Value);
        return true;
    }
}
#endif

此範例接受 -60、+30、0、12.5，拒絕空白、單獨正負號、NaN、Infinity、尾隨文字與超出 float 範圍的值；不接受科學記號。這是本題採用的簡單十進位格式。

完成後怎麼確認

先確認 ParseHitPushX 位於 Prepare 之外、WITH_EDITOR 範圍內，沒有重複定義。逐項核對程式：-60、+30、0、12.5 應可解析；空字串、30cm、NaN 與只有正負號應返回 false。這是讀碼檢查，實際驗證留到本階段建置與匯入完成後。

往下找到 Damage.Damage = Row.Damage;，在後面加入副本複製：

系統一：受擊推拉

依「定義資料與介面 → Init → Tick → End → 接入與測試」實作。先宣告所有方法，再依序寫函式定義；Init 呼叫的 End 會在步驟 4 補齊。

步驟 1：定義資料與介面

開啟 Fighting/FightingCharacter.h，在 AFightingCharacter 類別的 private 區加入以下成員。若需新增 private 區，放在該類別最後的 }; 前，不要加到其他 struct。狀態屬於受擊角色，每個角色各存一份。同一類別的成員函式可以呼叫另一個 AFightingCharacter 實例的 private 方法：

bool bHitPushActive = false; // 是否還有尚未完成的推拉。
float HitPushElapsed = 0.0f; // 本次效果已經過的秒數。
FVector HitPushTotalOffset = FVector::ZeroVector; // 命中當下決定的方向與總距離。
static constexpr float HitPushDuration = 0.15f; // 固定完成時間，單位為秒。

// Distance 使用 CSV 的正負公分值；由受擊角色保存自己的效果。
void InitHitPush(float Distance, const FVector& AttackerLocation);
void TickHitPush(float DeltaSeconds);
void EndHitPush();

完成後怎麼確認

先檢查 AFightingCharacter 的 private 區：三個狀態成員、0.15 秒常數與三個方法宣告各有一份。宣告應位於類別內；尚未接入遊戲，不會看到推拉。先完成步驟 2～5，再建置整套功能。

步驟 2：Init — 準備這次推拉

開啟 Fighting/FightingCharacter.cpp，在檔案末尾、所有既有函式的大括號之外新增以下完整函式。步驟 3、4 的完整函式可依序接在它後面。Init 一開始先 End，所以新值為 0 時也會停止舊效果；此處只記錄狀態，不立即移動角色。

void AFightingCharacter::InitHitPush(
    float Distance, const FVector& AttackerLocation)
{
    EndHitPush(); // 先取消舊進度，新值為 0 也會讓舊推拉停止。
    if (!FMath::IsFinite(Distance) || FMath::IsNearlyZero(Distance))
    {
        return;
    }

    // 從受擊者指向攻擊者；正值拉近，乘負值則反向推遠。
    FVector Direction = AttackerLocation - GetActorLocation();
    Direction.Z = 0.0f; // 保留角色高度，只處理水平位移。
    if (!Direction.Normalize())
    {
        return;
    }

    // 正規化後只保留方向，再乘距離得到整次效果的位移。
    HitPushTotalOffset = Direction * Distance;
    bHitPushActive = true;
}

完成後怎麼確認

現在先核對 InitHitPush 的函式定義位於 cpp 外層，開頭先 EndHitPush，且只記錄位移、不呼叫 AddActorWorldOffset。完成整套接線後可在斷點確認：非零距離使 bHitPushActive=true、HitPushElapsed=0，總位移的 Z=0；Distance=0 或方向近零時保持停用。

步驟 3：Tick — 分幀移動受擊者

在 Fighting/FightingCharacter.cpp 的 InitHitPush 函式結束後，新增以下完整函式：

void AFightingCharacter::TickHitPush(float DeltaSeconds)
{
    if (!bHitPushActive || DeltaSeconds <= 0.0f)
    {
        return;
    }

    // 最後一幀只計算剩餘時間，避免超過要求距離。
    const float NewElapsed = FMath::Min(
        HitPushElapsed + DeltaSeconds, HitPushDuration);
    // 本幀佔總時間的比例，就是本幀應完成的位移比例。
    const FVector FrameOffset = HitPushTotalOffset
        * ((NewElapsed - HitPushElapsed) / HitPushDuration);
    HitPushElapsed = NewElapsed;

    FHitResult Hit;
    AddActorWorldOffset(FrameOffset, true, &Hit); // true 啟用 Sweep，移動時檢查阻擋。
    if (Hit.bBlockingHit || HitPushElapsed >= HitPushDuration)
    {
        EndHitPush(); // 受阻或到期都結束，不繼續累積剩餘位移。
    }
}

例如要求推遠 60 公分，某一幀經過 0.015 秒，該幀要求移動 60 × 0.015 / 0.15 = 6 公分。最後一幀只補剩餘時間，不能每幀固定移動 6 公分，否則速度會受 FPS 影響。

完成後怎麼確認

先確認只使用本幀時間差計算 FrameOffset，而且 Sweep 參數為 true。整套建置後，無阻擋時以 60 公分、0.15 秒推拉觀察：若某幀 DeltaSeconds=0.015，該幀要求距離為 6 公分；不是每幀固定移動 6 公分。遇阻擋會呼叫 EndHitPush，不要求碰撞後仍走滿距離。

步驟 4：End — 停止並清除狀態

在 Fighting/FightingCharacter.cpp 的 TickHitPush 函式結束後，新增以下完整函式。End 只停止剩餘位移，不把角色送回起點；到期、碰撞、被新推拉取代或 EndPlay 都呼叫它。

void AFightingCharacter::EndHitPush()
{
    // 清除效果資料，但保留角色目前的位置。
    bHitPushActive = false;
    HitPushElapsed = 0.0f;
    HitPushTotalOffset = FVector::ZeroVector;
}

完成後怎麼確認

核對 EndHitPush 只清三個狀態，沒有 SetActorLocation 或回到起點的程式。整套完成後，在效果結束的斷點應看到 bHitPushActive=false、時間為 0、總位移為零向量，角色留在移動後的位置。

步驟 5：接入遊戲並測試

仍在 Fighting/FightingCharacter.cpp，於 AFightingCharacter::TryApplyHit() 找到 const int32 Deducted = ...，緊接其後加入以下程式。現有受擊角色變數名為 Target，查表結果為 Damage；原本的受擊反應判斷保留：

if (Deducted > 0)
{
    // this 是攻擊者，Target 才是要移動的受擊角色。
    Target->InitHitPush(Damage.HitPushX, GetActorLocation());
}

不要加上「HitPushX 不為 0 才呼叫」的條件，否則新的零推距傷害無法取消舊效果。防禦或沒有扣血時不呼叫 Init。

  1. 在 AFightingCharacter::Tick(float DeltaSeconds) 的 UpdateReaction(); 之後、RefreshOpponentDirection(); 之前加入一次 TickHitPush(DeltaSeconds);。不要放在「必須正在攻擊」的條件內，受擊角色在受擊動畫期間也要持續更新。
  2. 在既有 EndPlay 的 FinishReaction(true); 之後、Super::EndPlay(EndPlayReason); 之前加入 EndHitPush();，保留其餘清理。
  3. 不要在攻擊者接招結束或受擊角色的 StartReaction() 裡呼叫 EndHitPush；受擊反應停止速度不等於取消本題推拉。
  4. 保留命中候選先算完、再結算的流程。命中只 Init，後續角色 Tick 才移動。
  5. 在場地中央依序用 -60、30、0 測試，確認負推正拉、跨幀移動與正常停止；再靠近牆壁測碰撞停止。除錯時可觀察 Active、Elapsed 與實際位置，不需新增 UI。

完成後怎麼確認

完成本系統後先依「手動建置與匯入」建置、重開 Editor 並匯入測試值。-60 應平滑推遠、30 應平滑拉近、0 應不啟動推拉；防禦不產生新推拉，撞牆停止。若扣血正常卻完全不動，依序確認副本 HitPushX、Target 的 InitHitPush、角色 TickHitPush 是否真的被呼叫。通過後再做震動系統。

系統二：Director 鏡頭震動

同樣先定義資料與介面，再寫 Init／Tick／End，最後接到命中事件與 Director。Shake 的生命週期方法是供 Director 使用的 public 介面；狀態與效果常數是 private，不能把所有方法都設成 private。

步驟 1：定義資料與介面

建立 Source/TndaFighter/Fighting/Camera/FightingCameraShake.h。這是純 C++ 類別，不需 UCLASS 或 generated header。公開介面只提供生命週期與本地偏移，狀態放在 private：

#pragma once

#include "CoreMinimal.h"

class TNDAFIGHTER_API FFightingCameraShake
{
public:
    // Director 呼叫的生命週期；效果本身不查角色或操作相機。
    void Init();
    void Tick(float DeltaSeconds);
    void End();
    // 只讀取目前偏移；不會因多讀一次就加速計時。
    FVector GetLocalOffset() const;

private:
    bool bActive = false; // 是否正在震動。
    float Elapsed = 0.0f; // 本次震動已經過的秒數。
    static constexpr float Duration = 0.15f; // 總時長，秒。
    static constexpr float Amplitude = 2.0f; // 起始振幅，公分。
    static constexpr float Frequency = 20.0f; // 每秒擺動次數。
};

建立同目錄的 FightingCameraShake.cpp，檔案開頭加入 #include "Fighting/Camera/FightingCameraShake.h"。接下來 Init、Tick、End 與 GetLocalOffset 的實作都放在這個新 cpp，Director 不複製這些狀態與公式。

開啟 Fighting/Camera/CombatCameraShot.h，在 ECombatCameraShot 的 UpperBodyCloseUp 之後、enum 的 }; 之前加入：

// 已有值會寫入資產，保留 None=0 與 UpperBodyCloseUp=1。
Shake = 2 UMETA(DisplayName = "Shake"),

開啟 Fighting/FightingCharacter.h。在 AFightingCharacter 既有 private 區加入序號，在既有 public 區加入 getter。下列兩段要分開放置，不要為了貼片段而改變其他成員的存取權限：

// private 區：每出現一次需要震動的有效命中，就增加一次。
uint32 ShakeEventSerial = 0;

// public 區：CameraActor 可讀取，但不直接修改序號。
uint32 GetShakeEventSerial() const { return ShakeEventSerial; }

命中序號只表示「又有一次符合條件的命中」。換招或停止震動時都不重設角色序號；Director 記住已讀到哪一筆，就不會每幀重複觸發。

開啟 Fighting/Camera/FightingCameraTypes.h，在 FFightingCameraFrameInput 的 CpuShot 成員後、結構的 }; 前加入：

// 每幀傳遞目前序號；Director 比對是否出現新事件。
uint32 PlayerShakeSerial = 0;

步驟 3：Tick — 推進時間與提供偏移

在 Fighting/Camera/FightingCameraShake.cpp 的 Init 定義之後，新增以下完整函式：

void FFightingCameraShake::Tick(float DeltaSeconds)
{
    if (!bActive)
    {
        return;
    }
    // 時間不倒退，也不超過總時長；暫停時傳入 0 就保持進度。
    Elapsed = FMath::Min(
        Elapsed + FMath::Max(DeltaSeconds, 0.0f), Duration);
    if (Elapsed >= Duration)
    {
        End(); // 到期後 GetLocalOffset 會回傳零向量。
    }
}

Tick 只更新效果內部時間；沒有啟用就直接返回，時間到由效果自己呼叫 End。暫停時 DeltaSeconds=0，進度保持不變。

GetLocalOffset：讀取當幀偏移，不再推進時間

在同一個 Fighting/Camera/FightingCameraShake.cpp，接在 Tick 定義之後新增：

FVector FFightingCameraShake::GetLocalOffset() const
{
    if (!bActive)
    {
        return FVector::ZeroVector; // 沒有啟用時，不改變原構圖。
    }

    const float T = FMath::Clamp(Elapsed, 0.0f, Duration); // 限制有效時間。
    const float Fade = 1.0f - T / Duration; // 從 1 逐漸減至 0，讓震動收斂。
    // 正弦負責左右擺動，振幅乘 Fade 後逐漸減弱。
    const float Offset = Amplitude * Fade
        * FMath::Sin(2.0f * PI * Frequency * T);
    return FVector(0.0f, Offset, 0.0f); // 相機本地 Y 軸是右方向。
}

GetLocalOffset 不推進時間，也不需要知道雙方角色、事件序號或鏡頭 Pose。同一幀讀取多次會得到相同結果。

完成後怎麼確認

先確認 Tick 是唯一增加 Elapsed 的方法，GetLocalOffset 不改時間。整套完成後，Elapsed 隨遊戲時間增加；未啟用或到期時偏移為零。以 T=0.0125 秒檢查公式時，Fade 約為 0.9167、本地 Y 偏移約為 +1.833 公分，X/Z 為 0；時間到 0.15 秒則由 End 清為停用。實際每幀不一定剛好取樣到這個時間。

步驟 4：End — 清除震動效果

在 Fighting/Camera/FightingCameraShake.cpp 的 GetLocalOffset 定義之後，新增以下完整函式：

void FFightingCameraShake::End()
{
    // 停用後即使 Elapsed 歸零，GetLocalOffset 仍會直接回傳零。
    bActive = false;
    Elapsed = 0.0f;
}

GetLocalOffset 隨後回傳零向量，Director 合成時就回到原構圖。End 不修改命中序號，也不操作 CameraActor。

完成後怎麼確認

核對 End 只將 bActive=false、Elapsed=0，不改角色序號，也不搬動 CameraActor。整套完成後，End 之後呼叫 GetLocalOffset 必須得到零向量；即使 Elapsed 歸零，也不會再次開始震動。

讓 Director 持有與管理 Shake

開啟 Fighting/Camera/FightingCameraDirector.cpp，沿用步驟 1 已加入的 include 與 FImpl 成員。於 FImpl 的 Initialize() 的 BaseConfig = InBaseConfig; 之前插入：

Director 初始化先記住現有序號，避免重播之前的事件。每次命中只呼叫 Shake.Init，不重新初始化整個 Director。

在同一 FImpl 的 Update()，找到 const float SafeDeltaSeconds = FMath::Max(0.0f, DeltaSeconds);，緊接其後插入以下內容。不要修改檔案底部僅轉呼叫 Impl 的外層 Update；原有 ChooseWinner、轉場與 EvaluatePose 都保留：

// 任一方序號改變就有新事件；不依數字大小判斷。
const bool bNewShake =
    Frame.PlayerShakeSerial != LastPlayerShakeSerial ||
    Frame.CpuShakeSerial != LastCpuShakeSerial;
// 先記住已讀取的序號，避免下一幀重複啟動同一事件。
LastPlayerShakeSerial = Frame.PlayerShakeSerial;
LastCpuShakeSerial = Frame.CpuShakeSerial;

{
    Shake.Init(); // 新命中從 t=0 開始，同幀雙方觸發也只啟動一次。
}
else
{
    Shake.Tick(SafeDeltaSeconds); // 沒有新事件時，繼續原效果的進度。
}

新事件的這一幀從 t=0 開始，下一幀再推進時間，避免把命中前的整段 DeltaSeconds 算入新效果。t=0 的正弦偏移為 0 是正常的。雙方同幀出現新事件也只 Init 一次；事件在相機更新後才產生時，下一次 Update 會讀到。

同一 FImpl 的 EvaluatePose() 最後已有 SanitizePose(Result, NormalPose); 與 return Result;。只在它們前面新增偏移合成，末尾應如下，不要重複貼兩次 SanitizePose 或 return：

    Result.BoomRotation.RotateVector(Shake.GetLocalOffset());
SanitizePose(Result, NormalPose);

Director 只取偏移並轉換到世界方向，不計算正弦或管理效果內部時間。Result 是本幀重新算出的構圖，因此偏移不會累加。BoomRotation 不變，避免震動影響移動朝向。整合過程不需要更改 IFightingCameraShot。
