課前實作練習

課前實作練習 1｜把第一招放慢，會更容易接出下一招嗎？

細步驟解答

  1. 停止 PIE，開啟 _DataTable/CommandTable.csv，確認 ID 1 的 PlayRate=1.0、Link=3，ID 2、3 的 Link 空白。每題從這份教材基準開始；保留三招的輸入、動畫、傷害、Notify 與全域時間倍率。
  2. 在 Content Browser 找到 /Game/DataTable/DT_Command，右鍵選 Reimport，開啟資料表核對 ID 1 的 PlayRate 與 Link。開啟 /Game/Fighting/stage1 並進入 PIE，輸入控制檯指令 tnda.Debug.ShowCombatDebug on。
  3. 從 Idle 放開方向鍵，按 U 出右直拳。在 Preorder 剛開時短按一次 I，觀察 Y 預約與接招結果。重新從 Idle 出招，再於接近 Enable 時短按 I。各次嘗試只送一次下一招輸入，讓 Buffer 倒數與輸入時機容易對照。
  4. 停止 PIE，只將 ID 1 的 PlayRate 改為 0.5，儲存 CSV，Reimport DT_Command 並核對。重新進入 PIE，重做較早輸入與接近 Enable 輸入兩種操作，展示與正常速度的差異。
  5. 請學生指出 CSV 的改動、畫面的播放速度、接招窗口與 Buffer 倒數，分別說明較早輸入與接近 Enable 輸入的結果。驗收須聽到兩個效果：「窗口持續較久」與「提前輸入要等待更久，可能逾期」；接招是否更容易，須連同輸入時機與實際操作結果說明。
  6. 助教解說：半速同時拉長抵達 Enable 的等待時間，以及 Enable 到 Disable 的接招窗口；FFightingCommandBuffer::Lifetime 仍是 0.5 遊戲秒。接近 Enable 或在窗口內輸入可能較容易掌握；在 Preorder 剛開時提前輸入，則可能在開窗前逾期。用下方算例分別比較等待與窗口長度，再回到學生的操作結果。
  7. 展示完成後停止 PIE，將 ID 1 的 PlayRate 還原為 1.0，儲存、Reimport 並核對。再次進入 PIE 確認基準 X→Y 可操作，以 tnda.Debug.ShowCombatDebug off 關閉 Debug，再停止 PIE。

助教解說算例。 假設素材 0.2 秒時接受下一招輸入，Enable 在素材 0.5 秒，Disable 在素材 0.8 秒。以下採固定速度、持續播放、無暫停或時間倍率變化，且輸入未被覆寫或提前清除；數字供教學比較，實際端點依 Editor 與 Debug 核對。

比較項目 正常速度 PlayRate=1 半速 PlayRate=0.5
輸入後等到 Enable (0.5 − 0.2) ÷ 1＝0.3 遊戲秒 (0.5 − 0.2) ÷ 0.5＝0.6 遊戲秒
Buffer 期限 0.5 遊戲秒 0.5 遊戲秒
這筆提前輸入的結果 抵達 Enable 時仍有效，可嘗試接招 抵達 Enable 前已逾期
Enable 到 Disable 的窗口長度 (0.8 − 0.5) ÷ 1＝0.3 遊戲秒 (0.8 − 0.5) ÷ 0.5＝0.6 遊戲秒

帶讀重點：這筆在素材 0.2 秒送出的預約，在半速時會先逾期；玩家若在接招窗口內重新送出合法輸入，仍可立即嘗試接招。放慢後的操作優勢是窗口持續較久，提前預約則仍受 0.5 秒期限限制。學生應能依輸入時機解釋這兩種結果。

課前實作練習 2｜編輯並打出「右直拳 → 左鉤拳 → 轉身後踢」三連招

細步驟解答

  1. 停止 PIE，開啟 _DataTable/CommandTable.csv。確認上一題的 ID 1 PlayRate 已還原為 1.0，再依下表設定 Link。以 Montage 欄辨識動畫；CSV 既有 Title 可維持原值。
展示順序與動作 ID 既有 Title Montage Keys 本題 Link
1．右直拳 1 基本攻擊 AM_Attack_01 X 3
2．左鉤拳 3 第二攻擊 AM_Attack_02 Y 2
3．轉身後踢 2 右腳踢頭 AM_Attack_03 6,X 空白
  1. 基準已包含 ID 1 的 Link=3，本題將 ID 3 的 Link 由空白填成 2，ID 2 的 Link 維持空白。完成設定後的 CommandTable.csv 如下圖，黃色框標出兩次接招的 Link 設定。

  1. 儲存 CSV，在 Content Browser 對 /Game/DataTable/DT_Command 右鍵選 Reimport。開啟資料表，核對 ID 1 的 Link 為 3、ID 3 為 2、ID 2 空白，三招的 PlayRate 均為 1.0。若匯入報錯，先檢查 CSV 欄位與錯誤訊息，修正後重新匯入。
  2. 開啟 /Game/Fighting/stage1，進入 PIE 並開啟 tnda.Debug.ShowCombatDebug on。確認角色回到 Idle，放開方向鍵後按 U，出右直拳。第一招的 Preorder 開啟後，在適當時機短按 I，接出左鉤拳。
  3. 確認左鉤拳已開始，再觀察第二招自己的 Preorder／Enable 窗口。窗口允許時，按住朝向對手的方向並短按 U，接出轉身後踢。方向 6 依雙方相對位置判斷：對手在右側用 D，在左側用 A。朝向鍵須在按 U 當下按住，供系統保存方向。
  4. 以 U → I → 朝向對手＋U 完整展示三連招。每次下一招輸入配合目前招式的窗口；每個角色只有一筆 Buffer，等左鉤拳開始後再輸入第三招，可讓兩次交接各自完成受理與消耗。
  5. 展示後開啟 CSV，請學生指出 ID 1 → 3 → 2 與動畫 01 → 02 → 03 的對應，說明 ID 1 的 Link 允許左鉤拳、ID 3 的 Link 允許轉身後踢，以及第三招的 6,X 如何對應實際按鍵。驗收看完整銜接、兩次輸入時機及資料修改說明。
  6. 若第三招接不出來，依序檢查：DT_Command 的 ID 3 是否已匯入 Link=2、左鉤拳是否已開始、按 U 當下是否有相對方向 6、第二招窗口是否仍開啟，以及 Buffer 是否逾期。可先在第二招 Enable 開啟後輸入方向加 U，再練習提前預約。
  7. 完成展示後停止 PIE，將 ID 3 的 Link 還原為空白，保留 ID 1 的 Link=3 與 ID 2 的空 Link。儲存、Reimport，核對教材基準；重新進入 PIE 確認 X→Y，關閉 Debug，再停止 PIE。

備課驗證：CSV 設定與輸入對應已按教材資料核對；本次文件同步尚未執行 Reimport 或 PIE。授課前須排練正常速度／半速比較與兩次連續交接，確認實際窗口、動畫順序與還原結果。

課堂示範

課堂示範 1｜用 Montage Notify 設計招式的 Frame Data

示範重點

示範內容。 在右直拳的 Montage 時間軸上，指出開始與結束傷害判定的位置，以及接受下一招輸入、允許接招、結束接招的位置。調整既有 Notify 後，操作角色，觀察招式生效與接招時機的變化，完成後還原。

示範分兩次進行：先保持 Damage State 長度，將它移到 Preorder 與 Enable 之間另一個合法位置，觀察傷害判定開始與結束的時機；還原後，再只將 Enable 移到 DamageEnd 與原 Enable 的中點，觀察提前輸入如何較早接出左鉤拳。每次使用當次 Editor 讀取的素材位置計算，保存、重新起招驗證，完成後還原原值。逐頁操作與話術見詳細教師講稿「備課補充｜合法 Notify 調整」。

先以玩家看得到的動作帶讀標記：Damage State 決定傷害判定區間，Preorder 表示開始接受下一招輸入，Enable 表示可以接出下一招，Disable 表示接招截止。接著用 ReadMontage()／PhaseAt() 說明這些位置如何對應四階段，並保留 Preorder < DamageBegin < DamageEnd < Enable < Disable < Length 的順序。

CanPreorder() 對應 [Preorder, Disable)，CanLink() 對應 [Enable, Disable)。用素材 0.2 秒＝設計幀 12 的算例說明 Debug Frame，再連回課前的半速比較：等待 Enable 的時間與接招窗口都變長，Buffer 的 0.5 遊戲秒期限維持固定，接招結果取決於輸入時機。

為什麼排在這一週。 本週要讓學生編輯連招。先學會設定每招的傷害與接招時機，學生才能依照想要的操作節奏調整招式。

收尾影片與轉場。 示範 1 最後一張投影片放入使用者選定的完全理解Frame/幀數概念。先從 0:59｜快打 6 的 AttackPhase 觀察出招、生效與收招，再跳到 5:02｜取消，看目前動作如何轉接其他動作。各段講完重點後暫停，以「玩家在右直拳還沒結束時按下 I，程式如何記住輸入，並在允許接招時開始左鉤拳？」進入示範 2。

片段時間與用途依使用者提供，授課前須核看內容與停止位置。影片無法播放時，改用起手、生效、收招的示意，對照教材的 Enable 與下一招開始時機。快打 6 的取消規則作為概念對照，教材的實際接招條件由 Link、Buffer 與 Notify 決定。

課堂示範 2｜玩家按下下一招後，程式如何完成接招？

示範重點

示範內容。 角色出右直拳時，按下 I 準備接左鉤拳。帶學生看程式如何確認左鉤拳是允許的後續招式、保存這次輸入，以及在可以接招時開始播放左鉤拳。再比較提早按、適時按與太晚按的結果。

先從 SubmitCommand() 收到 Y 與方向開始，經 TrySelectLinkedCommand()／SelectCommand() 檢查第 1 招的 Link=3 與輸入條件，再由 FFightingCommandBuffer::Submit() 保存輸入。若已可預約但尚未到 Enable，回傳 Buffered，畫面繼續播放右直拳。

接著帶讀 Enable 通知如何經 HandleCommandLinkNotify() 呼叫 ConsumeCommandBuffer()，確認窗口與期限、取出並清除預約，再查找左鉤拳資料，交給 StartAttack(..., true) 嘗試播放。若在接招窗口內才按 I，成功接招會直接回傳 Started。

清除 Buffer 發生在重新選招與嘗試播放之前，所以選招或播放失敗時，這筆預約也已取用。舊招的命中狀態則在新招播放成功後才清理，帶讀時要分清這兩個時點。

比較四種按鍵時機：Preorder 前按下會被拒絕；Preorder 到 Enable 之間按下會先保存，期限內到達 Enable 才能接招；Enable 到 Disable 之間按下可立即嘗試接招；到達 Disable 後按下會被拒絕。接不到時，帶學生依序檢查 Link、攻擊與方向條件、目前窗口及 Buffer 期限。左鉤拳成功開始後，角色改用第 3 招自己的 Link；課前實作設定為 2，便能沿相同流程接出轉身後踢。

為什麼排在這一週。 學生已經能操作角色出招，本週要進一步把招式連起來。透過一次完整的接招操作，學生可以理解 Link、Buffer 與 Notify 各自負責什麼，並用來檢查自己編輯的三連招為什麼成功或失敗。

課堂實作 1｜編輯並打出右直拳與左鉤拳交替的六連招

題目

編輯 _DataTable/CommandTable.csv，新增需要的招式資料列並設定 Link，完成「右直拳 → 左鉤拳 → 右直拳 → 左鉤拳 → 右直拳 → 左鉤拳」。沿用 AM_Attack_01 與 AM_Attack_02 的動畫及既有招式設定。分享桌面，完整操作六連招，再開啟 CSV 說明資料列與連接順序。展示後還原教材設定。

參考答案

展示重點：依圖完成 1 → 3 → 4 → 5 → 6 → 7，儲存並 Reimport /Game/DataTable/DT_Command。在 stage1 從 Idle 放開方向鍵，以 U → I → U → I → U → I 操作；每次確認新招已開始，再配合該招的窗口輸入下一拳。請學生指出動畫如何重複使用，以及每列 Link 如何指定下一招。驗收後停止 PIE，移除本題新增的 ID 4～7，將 ID 3 Link 還原空白，保留 ID 1 Link=3、ID 2 Link 空白，再 Reimport。圖片為使用者提供的設定參考，完整六連招尚待 PIE 排練。

課堂實作 2｜出招過程很長時，如何讓提前輸入保留到接招？

題目

將第 1 號招式的 PlayRate 設為 0.1，模擬出招過程較長的招式。播放右直拳，固定在 Preorder 剛開啟時短按一次 I，嘗試接出第 3 號招式左鉤拳，觀察 Buffer 倒數與接招結果。

修改 Source/TndaFighter/Fighting/FightingCommandLink.h 中的 FFightingCommandBuffer::Lifetime，自行決定合適的期限，讓這筆提前輸入能保留到 Enable。完成建置後，保持 PlayRate=0.1 與相同的輸入時機，展示修改前後的接招成果。分享修改位置、設定值與選擇理由，說明期限如何配合第一招的播放速度與接招時機。展示後還原程式與 CSV。

參考答案

  1. 還原基準三列 CSV，確認 ID 1 Link=3、ID 2 與 3 Link 空白，以及原本的 Lifetime=0.5。將 ID 1 PlayRate 設為 0.1，儲存並 Reimport /Game/DataTable/DT_Command，開啟資料表核對。
  2. 在 stage1 進入 PIE，以 tnda.Debug.ShowCombatDebug on 開啟 Debug。從 Idle 放開方向鍵按 U，固定在 Preorder 剛開時短按一次 I，觀察預約先建立、倒數歸零，以及抵達 Enable 時的接招結果。每次嘗試只按一次 I，讓期限從同一次受理持續計算。
  3. 停止 PIE，在 AM_Attack_01 核對 Preorder 與 Enable 的素材位置；剛開窗輸入時，可用 Preorder 位置估算受理位置。依下方公式計算等待時間，讓學生自行選擇略大於等待時間的 Lifetime，並說明預留餘裕的理由。
  4. 處理未儲存資產，關閉教材 Editor 與 Live Coding。開啟 FightingCommandLink.h，將 static constexpr double Lifetime = 0.5; 的數值改為學生決定的期限。
  5. 在 FightingCharacter.cpp::SubmitCommand() 中，將 Command buffered 日誌固定文字 lifetime=0.5 改為 lifetime=%g，並在參數末尾加入 FFightingCommandBuffer::Lifetime，讓紀錄反映設定。保留日誌等級與其餘參數。
  6. 依教材交付的建置入口完整建置並重新開啟 Editor。保持 PlayRate=0.1，重新從 Idle 按 U，在 Preorder 剛開時短按一次 I，展示 Buffer 保留到 Enable 並接出左鉤拳。請學生分享設定值、等待時間算法與修改前後結果；若仍失敗，檢查受理時機、期限、Link、角色是否中斷及新程式是否已載入。
  7. 帶讀 IsPending() 的 Now < SubmittedAt + Lifetime、Remaining() 與 SubmitCommand() 排程 Timer 時使用的同一常數。期限延長讓預約可以等得更久；實際接招仍受 Enable、Disable、合法輸入與播放條件控制。
  8. 展示後停止 PIE 並關閉 Editor，還原 Lifetime 為 0.5 及本題日誌改動；將 CSV 的 ID 1 PlayRate 還原 1.0，保留 ID 1 Link=3、ID 2 與 3 Link 空白。完整建置並重新開啟 Editor，Reimport CSV、核對資料，再以基準速度確認 X→Y。關閉 Debug 並停止 PIE。若建置失敗，記錄原因與尚未完成的還原驗證。

期限怎麼算？ 在播放速度固定、動畫持續播放，且沒有暫停、時間倍率變化、輸入覆寫或提前清除的情況下：

等待時間＝（Enable 素材位置 − 接受輸入時的素材位置）÷ PlayRate
Lifetime > 等待時間

假設 Preorder 位於素材 0.2 秒，學生在剛開啟時輸入，Enable 位於素材 0.5 秒，則等待時間為 (0.5 − 0.2) ÷ 0.1＝3 遊戲秒：

Lifetime 這筆提前輸入的結果
0.5 秒 等到 Enable 前就已逾期
3.0 秒 恰好等滿 3 秒時已達期限，IsPending() 判定無效
3.5 秒 此算例有 0.5 秒餘裕，可保留到 Enable 並嘗試接招

以上素材位置與 3.5 秒設定為教學算例。實際答案依教材的 Notify 位置與受理輸入時機決定；驗收時確認學生能用計算與展示結果說明所選期限。Disable、攻擊中斷或結束仍可提前清除 Buffer。

備課驗證：本題依已讀原始碼設計，尚未實際修改 C++、建置或 PIE 比較；授課前須以 PlayRate=0.1 排練 Preorder 剛開時的單次輸入，核對實際等待時間及修改前後的接招結果。
